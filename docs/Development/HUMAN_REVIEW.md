# 독립 사람 검수 30건 지침

이 지침은 분류의 사람 정답을 준비한다. API 출력 검사 통과, 두 방법의 일치, 통계 경보 성능과 별개다. 현재 정답과 정확도는 미측정이다.

## 준비와 파일

`.venv/bin/python -m es.human_review --root <저장소> --quote-policy source-span-v1`은 API·`.env`·키를 읽지 않고 현재 demo에서 개발 시험 seed42 첫 50건을 제외한 독립 30건을 만든다. 별도 seed `human-review-v1`의 해시 순서로 미리 고정하며, 예측의 성공/실패나 불일치로 골라내지 않는다.

`data/private/human_review_independent30/blind.csv`만 검수자에게 제공한다. 익명 `review_id`와 실제 송신과 같은 정제 원문(최대 1,500자)이 있다. 원문 안 차종 표기는 임의로 삭제하지 않는다. 같은 디렉터리의 `mapping.csv`와 `manifest.json`은 관리자만 보관한다. 대응표에는 ODI 번호와 입력 해시, manifest에는 표집 규칙·모델·프롬프트/스키마·인용 정책·검수 지침 잠금이 있다. 두 파일과 기존 AI 출력·키워드 예측을 정답 작성 전에 검수자에게 보여주지 않는다.

## 사람이 채울 칸

- `gold_primary`: 아래 16개 코드 중 하나. **원문에 명시된 주 문제**를 선택한다. 차종의 알려진 결함이나 외부 조사 결과로 추측하지 않는다. 불명확한 내용 자체는 `other`일 수 있지만, 읽을 수 없거나 문맥이 부족해 판단을 못하면 상태를 `unjudgeable`로 남긴다.
- `review_status`: `clear` / `ambiguous` / `unjudgeable`. 빈 값은 아직 검수하지 않았다는 뜻이다. 여러 증상 사이 주 라벨이 애매하면 `ambiguous`와 대안·이유를 기록한다. 확정 전에는 정답을 억지로 채우지 않는다.
- `gold_evidence`: 판정을 지지하는 원문 구절. 원문에 실제 있는 문구를 복사한다. 단순한 문자열 일치만으로 판정의 의미가 맞다고 보지 않는다.
- `human_notes`: 혼동한 범주, 부정문·우려와 실제 발생의 구분, 정보 부족, 필요한 두 번째 검수 등을 남긴다.

우선 주 라벨만 평가한다. secondary·hazards·severity를 나중에 검수한다면 별도 항목과 지침을 정하고 주 라벨 정확도와 합치지 않는다. 같은 자료에서 키워드와 LLM을 같은 정답에 비교한다. 검수자는 AI 한국어 요약, 선택 인용, 예측 코드, 사후 조사 결과를 보지 않는다.

## 16개 범주의 기준 요약

| 코드 | 원문에서 확인할 내용 |
|---|---|
| fire_thermal | 화재·화염·연기·타는 냄새·용융·과열 |
| electrical_failure | 화재·연기 없는 전기/배터리/전자장치 이상 |
| loss_of_power | 주행 중 추진력·가속 능력 상실 |
| engine_stall | 엔진이 꺼지거나 정지 |
| engine_failure | 내부 엔진 손상·고착·오일 부족·엔진 교체가 주 문제 |
| airbag | 에어백 문제 |
| brakes | 제동 문제 |
| steering | 조향 문제 |
| seat_belt | 안전벨트 문제 |
| fuel_leak | 연료 누출 |
| transmission | 변속기 문제 |
| lighting | 등화 문제 |
| suspension | 컨트롤암·링크·볼조인트·스프링·스트럿 등 현가 문제 |
| structure_body | 문·걸쇠·후드·유리·트림·차체/프레임 부식 |
| tires_wheels | 타이어·휠 문제 |
| other | 위 분류로 명확히 판단할 수 없는 내용 |

원문에 여러 문제가 명시되면 주 문제를 먼저 고르고 애매함을 기록한다. 발생하지 않은 화재/사고를 우려한 문장, 부정문, 단순 리콜 통지를 실제 발생으로 읽지 않는다. 경험한 고장 없이 리콜 통지만 있는 신고는 현재 분류 지침처럼 해당 부품 범주로 분류한다. 원문 밖 원인·부품·공급사·위험 확률을 추가하지 않는다.

## 잠금·재개·대조

정답은 예측을 보기 전에 작성·확정한다. 애매한 건은 가능하면 다른 사람도 예측을 보지 않고 판정한다. 검수자가 한 명이면 단일 검수자라는 한계를 밝힌다. 상태와 정답을 확정하기 전에 모델 예측에 맞춰 바꾸지 않는다.

준비 명령을 다시 실행하면 정답·메모 파일을 새로 쓰지 않고 기존 원문/대응표/잠금값을 검사한다. 입력·모델·정책·지침이 바뀌거나 파일이 손상되면 중지한다. 모델이나 정책을 표본 결과로 개선하면 이 30건도 개발 자료가 되므로 새 독립 평가를 계획한다. 매번 파일을 지워 표본을 재추출하지 않는다.

기존 `data/labels/sample60_compare.csv`는 같은 seed42 개발 50건을 포함한 **개발 비교용**이다. 예측·AI요약이 보이고 원문 발췌가 520자이므로 독립 정답 작성용으로 쓰지 않는다. export 재실행은 기존 파일을 보존한다. 정답은 비공개 `blind.csv`에서 관리한다.

## 결과의 범위

고정 30건의 방법별 정답 일치 건수와 평가 분모, 미판정·애매함·출력 실패, 주요 오류 유형을 함께 보고한다. 미판정이나 API 실패를 몰래 빼지 않는다. 판정 불가가 있으면 30건 전체 중 판단 가능한 건수와 그 분모의 결과를 따로 표시한다. 사람이 아직 판정하지 않았으면 정확도 칸은 빈 상태다.

30건으로 16개 범주별 안정적인 성능, 드문 화재의 재현율, 전체 7,502건·다른 차종/시장 일반 정확도, 작은 차이의 LLM 우월성, 사고 예방·원인 확인·현업 시간 절감을 보장하지 않는다. 표본 성적과 작은 표본의 한계는 함께 기록한다.
