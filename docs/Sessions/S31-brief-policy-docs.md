# S31 — Step 10 대표 신고 요약 정책의 문서 정합성

- 시각: 2026-10-09 문서 정정·정합성 검사 완료
- 관련: SPEC Step 9·10, ADR-020·023·024, 이슈 #12 후속

## 목표
현재 ADR-024의 대표 신고 선택·기존 AI 요약 인용 방식과 문서 설명을 맞춘다. 과거 설계·준비 이력을 보존하고 Cloudflare Pages 배포 선택 및 사람 정답 검수 미완료 상태를 분명히 한다.

## 완료 기준
- [x] AGENTS 규칙 9·SPEC·계약·요청서 구조의 대표 요약 설명 일치
- [x] ADR-017 원안과 최초 기록 보존, ADR-023 대체 상태 표시
- [x] LLM_PROMPTS §1·§2 SHA256 불변 확인
- [x] 문서 전용 범위·diff 검사
- [ ] 부모 대상 Draft PR 생성 (결과는 총괄에 별도 보고)

## Codex에 맡긴 일
총괄이 이슈 #12 후속 문서 정합성을 배정했다. clean 관리 worktree를 재사용하고 최신 부모 a5c0783에서 codex/brief-policy-docs 브랜치를 만들었다. AGENTS 규칙 9, SPEC, 데이터 계약의 설명, LLM_PROMPTS §3, ADR-017 후속 설명, ADR-023 상태와 이 세션만 수정한다. 새 설계가 아니라 ADR-024·사용자의 확정 선택을 기존 설명에 반영한다. 공개 문자열 계약·코드·라벨링/선택 프롬프트는 변경하지 않는다. CODEX_LOG는 총괄 담당이다.

## 결과
- 부모 a5c0783와 비교해 LLM_PROMPTS §1·§2의 문자열과 SHA256이 동일함을 확인했다. §1: 56f29d4e6230fcd6798b99ca403cf8a2259d770fdd6e83faa7622c6508753886, §2: d20227365244157eba665b9dbbf575feb84a3e45ea4c7068f52119764f01a38a.
- 데이터 계약의 모든 코드 블록을 이전 버전과 비교해 데이터 구조·예시 문자열이 동일함을 확인했다. 기존 공개 문자열 계약·스키마·타입 변경 없음.
- ADR-017 최초 기록 전체가 새 파일의 접두부와 정확히 같고, ADR-023은 상태 한 줄만 달라진다. AGENTS도 규칙 9 외의 줄이 동일함을 확인했다.
- 변경 파일은 위 소유 범위의 문서 7개뿐이다. `git diff --check` 통과. 문서 정정이므로 새 코드 테스트를 작성하거나 실제 API·캐시·DB를 실행·수정하지 않았다.
- SPEC의 Vercel 배포 안내를 사용자 선택 Cloudflare Pages로 정정하고, §6 사람 검수 계획에 완료 정답 0·분류 정확도 미측정·후속 전문가 검수 미완료를 명시했다. 초기 계획과 자료 준비 이력은 보존한다.

## 사람이 검토하며 고친 것
- 사용자가 기존 신고별 AI 요약을 그대로 인용하고 번호를 연결하는 방식을 명시 선택했다. 기존 요약 의미와 신고 분류 정확도는 미측정이며 인용 연결을 정확도 검증으로 표현하지 않는다.
- 사람 검수 자료 준비와 완료 정답을 구분하고 AI 정답으로 대체하지 않는다(ADR-020).
