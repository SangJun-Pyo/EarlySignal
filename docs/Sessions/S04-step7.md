# S04 — Step 7 OpenAI 라벨링 시험 준비

- 시각: 2026-10-09 진행 중
- 관련: SPEC Step 7, ADR-004·012·014

## 목표와 완료 기준
- [x] Structured Outputs strict, 동시성 제한, 재시도, 즉시 JSONL 저장과 재개
- [x] 원문 인용 검증, 입력·모델·프롬프트 변경 시 캐시 무효화
- [x] 식별 패턴 정제와 유료 호출 없는 테스트
- [x] 사용자 키 설정 후 50건만 시험
- [ ] 측정 시간·토큰·비용을 사용자에게 제시하고 전체 실행 결정 받기
- [ ] 라벨 비교 표, 사람 검수용 30건 준비

## 구현과 검수
Astra가 구현, 별도 검수자가 재시도 성공 시 이전 인용 오류 통계 누락을 발견. 성공 레코드에도 prior_errors/attempts를 남기고 회귀 테스트 추가.

## 모델과 비용 기준
`gpt-4.1-mini-2025-04-14`를 기본 시험 모델로 고정한다. 기존 temperature=0·Chat Completions·JSON Schema 계약에 맞는다. [공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-4.1-mini)를 2026-10-09 확인: 입력 $0.40, 캐시 입력 $0.10, 출력 $1.60 / 100만 토큰. 실제 계정 청구액이 아닌 usage 기반 추정임을 표시한다.

## 사람의 결정
50건 시험만 승인. 전체 실행은 측정 결과 확인 후 결정. 정답 라벨은 사람이 검수하기 전까지 미기입.

## 실제 시험 결과와 수정
2026-10-09 10:21 KST 50건 시험은 성공 응답 0건. HTTP429의 원인을 별도 읽기·짧은 진단으로 확인한 결과 `credit_balance_exhausted` / `insufficient_quota`였다. 사용자가 행사 키·크레딧을 확인하기로 했고 추가 유료 요청을 멈췄다. 사용량이 반환되지 않아 비용은 미측정이다.

초기 구현은 새로운 quota 오류 코드를 일시 속도 제한으로 취급해 재시도했다. 응답 code/type의 중첩 형식까지 확인하여 quota에서는 대기 요청·재시도를 즉시 중지하도록 고쳤다. 별도 검수자의 유료 호출 없는 5개 테스트로 영구 quota 오류 중지와 일시 rate limit 재시도를 구분해 확인했다.

## 크레딧 반영 후 재시험과 ADR-014

2026-10-09 크레딧 반영 후 실제 50건 재시험은 검증 통과 6건, 실패 44건이었다. 반환 응답 10회의 기록은 입력 8,349 토큰·출력 1,230 토큰, usage 기준 $0.0053076이다. 응답의 인용 불일치 시도는 4회였다. 이는 라벨 정확도 또는 전체 50건 완료 비용이 아니다. 후속 진단에서 `rate_limit_exceeded`, 잔여 요청 0, `Retry-After: 1728`을 확인했다. 시험 전체가 끝나지 않았으므로 기존 파일의 전체 비용·처리량 환산치는 사용하지 않는다.

ADR-014에 따라 다음을 수정했다. 이 수정과 검증에서는 실제 API를 호출하지 않았다.

- seed42 순서의 첫 50건을 먼저 고정한 뒤 캐시를 제외한다. 같은 `--limit 50` 재개가 다음 신고로 표본을 넓히지 않는다.
- `Retry-After` 초·HTTP 날짜를 해석한다. 60초 이하는 대기 중인 작업에 공유하고, 이를 넘으면 진행 중인 응답만 회수한 뒤 남은 작업을 보류한다.
- 키 SHA256·모델별 대기 시점을 `data/private/`의 비공개 파일(권한 0600)에 저장한다. 조기 재실행은 API를 호출하지 않고 같은 고정 표본을 재개 대상으로 보고한다. 키 원문과 응답 본문은 저장하지 않는다.
- 보고서에 고정 표본 안의 캐시 수·완료/대기 수·재개 번호·보류 사유·재개 가능 시점을 남긴다. 미완료 또는 캐시 재개 회차는 전체 비용·처리량 추정치를 null로 둔다.
- 독립 검수에서 추가 요청한 known identifier 검사도 캐시 저장 전에 수행한다. 영문 지명 뒤 한국어 조사가 붙는 요약도 거부한다.

유료 호출 없는 라벨러·quota·Retry-After 테스트 **26 passed**. 고정 표본 재개, 다른 표본 캐시 수 제외, 서버 대기 시간 경계, 대기큐 중단, 이미 진행 중인 응답 보존, 조기 재실행 차단, 키별 분리, 실제 대기 만료 뒤 재개를 확인했다. 독립 검수는 별도 R02 기록으로 남긴다.

## 후속 결과: 고정 50건 출력 검사 완료

서버 대기 종료 뒤 같은 표본을 재개해 36건까지 검증·저장했다. 남은 14건은 인용이 원문과 다르거나 길이 제한을 넘었다. ADR-018에 실패 진단과 원문 후보 ID 선택 방식을 먼저 기록하고 구현·독립 검수했다. 기존 36건을 유지하고 같은 14건을 처리해 **50/50 출력 검사를 완료**했다. 실제 호출·비용·수정 이력은 [S16](S16-step7-quality.md)에 보존한다.

이 수치는 API 출력의 형식·인용 검사 통과 건수이며 사람 정답 기반 분류 정확도가 아니다. 50건은 구현 진단에 사용한 개발 표본이므로 최종 정확도 표본과 분리한다. 전체 7,502건 라벨링과 독립 사람 정답 검수는 아직 실행하지 않았다.
