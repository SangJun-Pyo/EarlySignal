# S04 — Step 7 OpenAI 라벨링 시험 준비

- 시각: 2026-10-09 진행 중
- 관련: SPEC Step 7, ADR-004·012

## 목표와 완료 기준
- [x] Structured Outputs strict, 동시성 제한, 재시도, 즉시 JSONL 저장과 재개
- [x] 원문 인용 검증, 입력·모델·프롬프트 변경 시 캐시 무효화
- [x] 식별 패턴 정제와 유료 호출 없는 테스트
- [ ] 사용자 키 설정 후 50건만 시험
- [ ] 측정 시간·토큰·비용을 사용자에게 제시하고 전체 실행 결정 받기
- [ ] 라벨 비교 표, 사람 검수용 30건 준비

## 구현과 검수
Astra가 구현, 별도 검수자가 재시도 성공 시 이전 인용 오류 통계 누락을 발견. 성공 레코드에도 prior_errors/attempts를 남기고 회귀 테스트 추가.

## 모델과 비용 기준
`gpt-4.1-mini-2025-04-14`를 기본 시험 모델로 고정한다. 기존 temperature=0·Chat Completions·JSON Schema 계약에 맞는다. [공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-4.1-mini)를 2026-10-09 확인: 입력 $0.40, 캐시 입력 $0.10, 출력 $1.60 / 100만 토큰. 실제 계정 청구액이 아닌 usage 기반 추정임을 표시한다.

## 사람의 결정
50건 시험만 승인. 전체 실행은 측정 결과 확인 후 결정. 정답 라벨은 사람이 검수하기 전까지 미기입.

## 실제 시험 결과와 수정
2026-10-09 10:21 KST 50건 시험은 성공 응답 0건. HTTP429의 원인을 별도 읽기·짧은 진단으로 확인한 결과 `credit_balance_exhausted` / `insufficient_quota`였다. 사용자가 행사 키·크레딧을 확인하기로 했고 추가 유료 요청을 멈췄다. 사용량이 반환되지 않아 비용은 미측정이다.

초기 구현은 새로운 quota 오류 코드를 일시 속도 제한으로 취급해 재시도했다. 응답 code/type의 중첩 형식까지 확인하여 quota에서는 대기 요청·재시도를 즉시 중지하도록 고쳤다. 별도 검수자의 유료 호출 없는 5개 테스트로 영구 quota 오류 중지와 일시 rate limit 재시도를 구분해 확인했다.
