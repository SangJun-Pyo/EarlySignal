## 결과
`source_manifest.json`의 신고 ZIP3개·조사 ZIP1개를 `ingest.py` 상수와 다운로드 URL 구성에 대조했고4개 모두 일치했다. README에 공식 직접 링크와 용도를 표시했다. 전체 ZIP 수집 기간과 고정 데모7,502건 LLM 분류, 공개 콘솔9개 차종·2018-03~10을 구분했다. 조사 파일은 사후 비교용이며 탐지 입력이 아님을 명시했다.

ADR-025·발표 근거표·발표자 노트에 이미 사용된 PE19-003·004, DP18-003, 리콜18V907·934 보고서와18V934 안내문6개를 사후 사건 설명 표3행으로 연결했다. 개별 신고의 원인을 리콜과 동일시하지 않는다. 총괄이 공식4ZIP+6PDF 링크10개를 HEAD 요청으로 확인해 모두 HTTP200이라고 보고했다(ZIP `application/octet-stream`, PDF `application/pdf`). 원본 ZIP 다운로드는 하지 않았다. PDF2개 웹 파서는 internal error였고 HEAD 접근은 정상이라는 경위도 전달받았다. 이 세션 구현자가 직접 HEAD 검사했다고 주장하지 않으며, 링크 접근 가능성은 현재 원격 파일이 기존 manifest와 동일 바이트라는 증거가 아니다. 관측일을 다운로드일로 바꾸지 않았다.

파이프라인 import·`pyproject.toml`, 웹 `package.json`·`layout.tsx`·CSS, 발표 빌더와 그림 빌더의 import·폰트 등록을 읽었다. NumPy·PyYAML·python-dotenv·jsonschema, ReportLab·Matplotlib, 웹의 IBM Plex Sans KR와 Mono 사용을 추가했다. PDF·그림은 Sans KR 사용으로 구분했다. RAG/pgvector는 외부 사용 자산에 넣지 않았으며 기존 ADR-017 문단 전체를 검증·남은 가정 절로 이동해 보존했다. 원본 미커밋·정규식 개인정보 검사 한계도 유지했다.

합성 검사 스크립트로 manifest/ingest 파일4개와 README 직접 URL4개 일치, 변경 대상 문서의 로컬 Markdown 링크40개 존재, ADR-017 문단1회·개인정보 한계 보존·외부 자산의 RAG 미포함을 확인했다. `git diff --check` 통과. API 호출·환경변수/키 열람·원본 다운로드·DB 접근·PDF 재생성·제품 코드 변경은0회다. 문서 변경이므로 제품 테스트를 새로 실행하지 않았다.
