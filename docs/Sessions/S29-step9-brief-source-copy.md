# S29 — Step 9 대표 신고 요약의 출처 표시

## 목표
화면과 조사 요청서에서 대표 신고의 기존 AI 요약을 그대로 인용한다는 사실을 표시한다. 새로운 종합 서술이나 의미 정확도 검증으로 오해하지 않도록 한다.

- [x] 웹 테스트·타입 검사·정적 빌드 통과
- [ ] Step 커밋·부모 브랜치 대상 Draft PR·최신 head CI 확인

## Codex에 맡긴 일
총괄이 이슈 #12 후속 표시 작업을 배정했다. clean 상태의 기존 validation-source managed worktree를 재사용하고 최신 부모 e4d7c38에서 codex/brief-source-copy 브랜치를 만들었다. 소유 범위는 web/lib/request.ts, web/components/workspace.tsx, 필요한 웹 테스트와 이 세션이다. 파이프라인의 selected_ids 1~3 선택·기존 summary_ko 인용 구현과 ADR-024는 별도 담당이다. 공개 데이터·root checkout·DB·API·키·private 파일에는 접근하지 않는다.

## 결과
- `npm test` → 웹 23 tests 통과. 요청서에서 대표 요약 원문 보존·번호 중복 제거·기존 AI 분류 출처·의미 대조 필요 표시, 미준비 및 인용 보류 상태를 검사한다.
- `npm run typecheck`, `npm run build` → 통과. 기존 정적 export 구조를 유지한다.
- `git diff --check` → 통과. 화면과 요청서는 제목·검토 문구·미준비 안내 문자열을 공유한다. 인용 신고의 출처 메모는 “대표 요약 인용”으로 바꿨다.
- 이번 변경은 웹 표시와 합성 회귀 검사만 다룬다. 인용 연결 구조를 의미 정확도나 전문가 분류 검수로 표시하지 않는다. CODEX_LOG 색인은 총괄 담당이다.
- Draft PR #16의 첫 head 74b7cd2 실제 CI run 37880041858에서 Python 3.10·3.13 및 웹 테스트·타입 검사·빌드 3개 job과 Cloudflare check가 성공했다. 구현자 외 독립 검수를 통과한 뒤, 총괄이 대표 요약 각 줄이 붙어 보이는 표시 보완을 요청했다. brief-box 본문에 whitespace-pre-line을 적용해 각 (#신고번호) 요약의 개행을 보존한다. 추가 테스트 파일 없이 새 head의 CI를 확인한다.

## 사람이 검토하며 고친 것
- 사용자가 “신고별 AI 요약을 그대로 인용하고 번호 연결 (추천)”을 명시 선택했다는 총괄의 전달을 반영한다. 답변 전 검토본과 명시 선택 이후 구현을 구분한다.
- 기존 신고별 AI 요약의 의미와 분류 정확도는 미측정이다. 인용 형식 확인을 정확도 검증으로 표시하지 않는다.
