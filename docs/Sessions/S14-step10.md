- 시각: 2026-10-09 (오프라인 구현·검증)
- 관련: SPEC Step 10, ADR-009·012·013·014·015

## 목표
console.json 범위의 경보 칸에 실제 LLM 상황 요약 생성 경로를 만들고, 첫 통계문과 같은 칸 신고 인용을 검증해 요청서 3번 항목에 연결한다.

## 완료 기준
- [x] 완성된 LLM 콘솔만 받아 최대 10건의 같은 칸 근거로 bounded 생성·캐시·재시도한다.
- [x] 인용·숫자·개인정보·미래 정보·API 중지 경계를 유료 호출 없는 테스트로 검증한다.
- [x] 검증된 캐시만 LLM export에 연결하고 미생성·실패는 빈 briefs로 남긴다.

## Codex에 맡긴 일

## 독립 검수 후 수정과 재검증
- 별도 검수자가 공백 없는 마침표 뒤 무인용 문장, 실제 심각도 1·2 간 정렬 누락, `열한 명`·`십 명`·`한 사람` 수량 검사 누락을 재현했다.
- 문장 경계는 `. ! ? 。 ！ ？ ｡` 뒤 공백이 없어도 나누고, 영어 초기 약어와 인용 번호 목록·종결 따옴표는 회귀로 보존했다. 한글 복합·한자계 수사와 수량 단위는 보수적으로 거부한다. 이는 의미 검수나 모든 자연어 수량의 완전한 탐지를 보증하지 않는다.
- 근거 우선순위는 화재 > 부상 > 충돌 > 실제 severity(1~3 내림차순)로 고쳤다. severity 4는 유효한 계약 사례가 아니므로 검수·회귀는 실제 1·2로 수행했다.
- 생성 검증과 캐시 재검증에 동일한 검사를 적용해 이전에 통과한 무인용·임의 수량 문장도 export에서 제외한다.
- 관련 테스트 **79 passed in 4.65s**. 독립 검수자가 별도로 같은 **79 tests**를 실행해 통과하고 세 우회를 직접 재현해 차단을 확인했다.
- 수정 후 전체 Python 테스트 **143 passed in 26.47s**, `py_compile`·변경 파일 `git diff --check` 통과. 전체 수에는 동시에 추가된 라벨러 회귀도 포함되며 이 세션은 라벨러를 수정하지 않았다.
- 수정·검수에서 실제 API 호출·API 키 열람·공개 데이터 변경·커밋은 수행하지 않았다.
