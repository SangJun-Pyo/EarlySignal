# S06 — Step 6 백테스트

- 시각: 2026-10-09 완료
- 관련: SPEC Step 6, ADR-003, ADR-005, ADR-011

## 목표
사전 등록한 38개 사례와 36개 대조를 dev/holdout으로 평가하고 실패·업무량을 공개한다.

## 완료 기준
- [x] 2×2 실제 결과와 대표 사례 lead 확인
- [x] 규칙·키워드를 holdout 성능에 맞춰 변경하지 않음
- [x] 38개 사례 기준 완료월 cutoff 결과 정확 일치

## Codex에 맡긴 일
확인가능일=경보 월 다음달1일. 사전 명세를 보존해 첫 신호 검색은 month∈[odate−12개월, odate+6개월], primary_hit는 month∈[odate−12개월, odate−1개월). lead와early 여부는 확인가능일로 계산. available 날짜로 창을 이동한 정의는 별도 민감도만 공개. 실패를 제거하지 않고 결과를 파일에 저장한다.

## 결과
주 지표(사전 월 기준): dev사례9/19·대조0/19, holdout사례7/19·대조1/17. 사전dev8/19와1건 차이, holdout·대조 일치. PE19003=209일(17건/6.8333), PE19004=240일(14건/4.4167), PE20016=missed(사전late와 불일치). 모든38사례/36대조의 실패·지연 포함 data/backtest_kw.json 저장. 대조군 업무량36경보/390그룹월=0.0923경보/그룹월. 단일차종만 동일규칙 민감도 사례8/20·대조1/19(data/results/sensitivity_single_group_kw.json; 실제파일의 값 우선). 38개 완료월 미래접수차단 정확 일치.

## 문제와 해결
사전 코드가 제공되지 않아 키워드 패턴 완전 동일성을 보장할 수 없다. 현재 패턴은 SPEC 예시와 범주 정의를 먼저 고정한 뒤 평가했다. 초기에는 available 날짜로 창을 정의하여 dev10/19·대조1/19/holdout8/19·대조1/17이 나왔고, 부모 에이전트가 사전등록 월 기준 보존을 지시해 주 지표를 복원했다. 초기 숫자를 숨기지 않고 available_date_sensitivity에 남겼다. 포아송 파라미터·정규식은 결과에 맞춰 변경하지 않았다.
