# S08 — Step 9-1·2: 신고 원문, 신호와 근거

- 시각: 2026-10-09 (Asia/Seoul), 구현·정적 검증 완료 / 브라우저 검수 대기
- 관련: SPEC Step 9, ADR-002, ADR-007, ADR-009

## 목표
실제 console.json으로 월별 신고 원문과 차종×증상 신호를 보여주고, 담당자가 원문을 검토해 인용·제외한다.

## 완료 기준
- [x] 정적 웹 빌드 성공 (`npm run build`, Next.js 16.4.0)
- [x] 기준 월 이후 실제 값은 운영 화면에서 차단 (`getAsOf` 및 순수 함수 테스트)
- [x] 실제 데이터의 신고·통계·발생 상황 집계 연결 (정적 통합 검수)
- [x] 인용·제외 상호 배타적 처리, 집계 필터·추이 구현
- [ ] 실제 브라우저에서 필터·추이·인용·제외 상호작용 확인 (Astra 통합 검수)

## Codex에 맡긴 일
아스트라가 업무 흐름·계약을 지휘하고 웹 담당 에이전트가 Next.js 정적 화면을 구현. 파이프라인 담당과 데이터 계약으로 연결하며 요청서·기준시점 순수 함수는 지휘 에이전트가 구현.

## 결과
`npm test` 17/17 통과, `npm run typecheck` 통과, `npm run build` 통과. `web/out` 정적 출력의 `/` 및 `/data/console.json` HTTP 200을 확인했다. 로컬 정적 서버에서 Astra가 실제 브라우저 검수를 이어간다. 공개 배포는 아직 하지 않았다.

현재 키워드 분류 출처를 표시하며, 아직 내보내지 않은 LLM 요약을 만들어 표시하지 않는다. 발생 상황에서 NHTSA 기록·키워드 규칙·미측정을 구분한다. 기준 월 변경은 선택·검토·판단을 초기화하며, 그래프와 원문은 `getAsOf`의 해당 월까지 값만 사용한다.

## 문제와 해결
| 문제 | 원인 | 해결 | 누가 |
|---|---|---|---|
| 상황 요약이 미생성 | API 크레딧 부족 | 원문과 NHTSA 기록을 보여주고 미생성 상태 명시 | Codex |
| 원본 다운로드일을 추정할 위험 | 제공 ZIP의 다운로드일 미확인 | footer에 다운로드일 미확인과 로컬 파일 확인일을 구분 | 웹 담당 |
| 개발 서버가 작업 지침 파일을 자동 생성 | Next.js 16.4 기본값 | 설치된 Next 타입·실행 코드에서 지원 확인 후 `agentRules: false` 사용 | 웹 담당 |
