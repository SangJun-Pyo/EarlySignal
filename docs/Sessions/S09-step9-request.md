# S09 — Step 9-3: 조사 요청서와 검증 결과

- 시각: 2026-10-09 (Asia/Seoul), 구현·정적 검증 및 브라우저 검수 완료
- 관련: SPEC Step 9, ADR-009, 데이터 계약 v1

## 목표
근거가 연결된 요청서를 확정·저장·다운로드하고 판단 기록을 남긴다. 검증 결과는 사후 확인 화면에서 보여준다.

## 완료 기준
- [x] 화면과 Markdown이 같은 순수 함수 출력 사용
- [x] 판단 선택 후 실제 저장 시각 기록 (함수 테스트 및 정적 통합 검수)
- [x] localStorage 읽기·쓰기 예외 처리 및 JSON 다운로드 구현
- [x] 실제 dev/holdout·실패 사례와 미검증 한계 연결
- [x] 요청서 테스트 및 정적 빌드 성공
- [x] 실제 브라우저에서 저장·파일 다운로드·새로고침 후 기록 유지 확인

## Codex에 맡긴 일
웹 담당이 종이 문서와 판단·저장 UX를 구현하고, 아스트라가 요청서 순수 함수와 인용·미래 정보 차단 테스트를 작성한다.

## 결과
`npm test` 17/17, `npm run typecheck`, `npm run build` 통과. 원문 검토에서 생성한 요청서와 Markdown 다운로드가 `createRequest`의 동일 출력을 사용한다. 저장 시 Markdown을 자동 다운로드하며 재다운로드 버튼과 판단 기록 JSON 다운로드를 제공한다. 같은 문서번호를 다시 저장해도 이전 결정을 지우지 않고 실제 저장 시각별로 남긴다. 브라우저 저장 실패 때는 파일로 보관하도록 안내한다.

독립 검수 R02에서 요청서 문서번호 충돌, 잘못된 근거 날짜·건수, 짧은 근거 밖 인용, 제외 근거의 AI 재인용을 검사·보완했다. 웹은 기준 월 근거만 표시하고 요청서 생성 오류를 숨기지 않는다. 공개 제품에서 LLM 상황 요약이 없으면 미생성으로 표시한다.

## 문제와 해결
| 문제 | 원인 | 해결 | 누가 |
|---|---|---|---|
| 과거 작성일 오해 위험 | 과거 데이터 데모 | 분석 가능일과 실제 저장 시각을 따로 표시 | Codex |
| 동일 신호 저장 시 이전 판단 소실 | 문서번호로 기존 기록 대체 | 저장 시각별 append 기록 및 복합 표시 key | 웹 담당 |
| 잘못된 메모 인용을 입력하면 수정 폼이 사라짐 | 초안 검증 실패 때 요청서 전체를 빈 화면으로 전환 | 오류·입력 폼 유지, 저장 비활성화, 메모 수정으로 복구 | 웹 마무리 담당 |
