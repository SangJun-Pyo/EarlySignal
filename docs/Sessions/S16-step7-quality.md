# S16 — Step 7 인용 검증 실패 진단

- 시각: 2026-10-09, 비텍스트 진단 구현·로컬 검증 완료 / 실제 진단은 주 작업에서 진행
- 관련: SPEC Step 7, ADR-012, ADR-014, ADR-018

## 목표
OpenAI 라벨링 50건 시험의 인용 검증 실패를 구분하고 승인된 고정 표본 안에서 재개한다. SPEC 전체 완료 기준(7,502건 라벨·스키마 위반 0·키워드 대비 일치율)은 이번 승인 범위가 아니다.

## 완료 기준
- [x] 검증 조건과 캐시 식별자를 유지한 채 비텍스트 인용 실패 진단을 저장한다.
- [x] 1건·1회 제한 실행으로도 원래 cohort·사용량 원장이 보존되는 것을 mock 테스트로 확인한다.
- [x] 관련 테스트의 실제 결과를 기록한다.

## Codex에 맡긴 일
인용 검증 실패 원인을 안전하게 진단한다. 하위 작업에서는 API 호출과 비밀값 읽기를 하지 않으며, 실제 추가 호출은 주 작업에서 동일 50건 범위로만 관리한다.

- 주 작업의 두 번째 1회 진단(`2026-10-09T02:22:45.609462+00:00`): 인용 165자, 정확 일치와 대소문자/공백/따옴표 정규화 일치 모두 실패. 최장 연속 일치 75자(45.45%)이며 정규화 후에도 같았다. 추정 비용 $0.0005676. 단순 길이·대소문자·공백 문제라는 가설은 이 응답에 대해 배제되며 자동 문자열 복구는 하지 않는다. 실제 의미상 재서술 여부는 응답 원문을 저장하지 않아 판정하지 않는다.
- 후속 구현: `quote_selection_fallback=True`인 경우 신고당 한 실행 내 최대 1회, 실제 송신 원문에서 추출한 후보 ID만 모델이 고르게 한다. 기존 분류·요약은 바꾸지 않고 선택된 offset의 원문을 인용으로 저장한다. 사용량 원장의 `stage=quote_selection`과 캐시의 `quote_selection`에 추가 생성 출처를 기록한다. 후보 문맥이 경계에서 잘릴 수 있어 사람 검수가 필요하다.

## 문제와 해결
| 문제 | 원인 | 해결 | 누가 |
|---|---|---|---|
| 실패 원인을 구분할 수 없음 | 빈 인용·원문 불일치·길이 초과가 같은 코드 | 미검증 텍스트 없이 시도별 진단 추가 | Codex |
| 작은 진단 실행 시 표본 축소 위험 | limit은 고정 표본 크기 | 별도 실행 건수 제한, cohort 유지 | Codex |

## 실제 고정 50건 시험 완료
- 독립 검수자는 관련 **65 tests passed**, 5.23초와 추가 구간 경계 6개를 확인했다. 기존 36건 캐시 파일 해시가 바뀌지 않았고 추가 API 호출이나 키 열람은 없었다.
- 총괄의 첫 실행 `2026-10-09T02:32:20.867288+00:00`: 미완료 1건, 라벨 응답 1회와 후보 선택 1회, 검증 성공. 37/50 완료. 입력 1,628·출력 143토큰, 반환 usage 추정 $0.0008800, 5.743초.
- 선택된 인용의 원문 slice 일치를 재확인했다. 원문 전체에 연기·화재·휘발유 누출 진술이 있지만 한 인용 구간은 일부 증상만 담는다. 이 한 건의 Codex 대조는 사람 정답 기반 정확도 검증으로 세지 않는다.
- 다음 실행 `2026-10-09T02:32:55.884767+00:00`: 남은 13건 전부 검증 성공, 라벨 13회+후보 선택 13회. 입력 20,296·출력 1,782토큰, 반환 usage 추정 $0.0109696, 29.862초. API 중단 없음.
- 같은 고정 표본 **50/50의 스키마·원문 인용·민감정보 검사를 재실행했고, 후속 선택 14건의 원문 offset 일치도 확인**했다. 이는 출력 검사 완료이며 분류 정확도 100%가 아니다. 의미상 정답은 아직 사람이 평가하지 않았다.
- 원문 불일치·길이 초과의 최초 실패와 후속 선택 이력은 원장에 남겼다. 신규 정책에 앞서 발생한 유료 실패와 진단 비용도 누적 비용에 포함한다. 집계 검산은 `data/results/llm_pilot_completed.json`에 별도 기록한다.
- CLI에도 `--max-attempts`, `--max-new-rows`, `--quote-selection-fallback`을 노출해 제한 실행을 재현할 수 있게 했다. `label-llm --help` 확인. 최종 전체 Python **161 tests passed**, 25.02초.
