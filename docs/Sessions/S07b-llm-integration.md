## 문제와 해결

## 사람이 검토하며 고친 것
사용자는 50건 비용 보고 후 전체 실행을 결정한다고 명시했다.

## 다음 세션으로 넘길 것
전체 라벨 실행은 사용자 승인 후 주 에이전트가 맡는다.

## 재현 명령
- `python -m es.cli import-llm`: 현재 demo의 모델·프롬프트·정제 입력 해시가 맞는 성공 캐시 전부를 검사하고 테이블로 가져온다.
- `python -m es.cli aggregate --method llm` / `detect --method llm`: 같은 완전성 검사를 다시 수행한다.
- `python -m es.cli export --method llm`: 완전성 검사 후 demo 재집계·탐지, LLM 콘솔·3사례 상세·동일 모집단 비교와 sample60_compare.csv를 만든다. 실제 API 호출은 없다.
- `backtest --method llm`은 거부한다. 38사례·36대조 주 결과는 키워드 기준선으로만 계산한다.

## 완료 검증
전체 Python 76개 통과 후 비용 경계 테스트를 추가했고, 변경 범위 테스트(import/contract/request) 31개가 통과했다. 합성 완성 캐시는 콘솔·LLM 상세·manifest·동일 모집단 비교까지 실행했다. 이 합성 테스트는 모델 정확도·실제 LLM 전체 실행 증거가 아니다.

실제 캐시로 LLM export를 시도한 시점에 현재 해시 기준 6/7,502건만 일치하여 7,496건 누락·오래된 캐시로 중단됐다. 공개 키워드 파일과 DB는 변경하지 않았다. 이후 키워드 export를 다시 실행해 42파일 완료를 확인했다.

독립 검수의 비용 누락 지적을 반영했다. 현재 cache_key에 연결되는 모든 실행의 유료 재시도를 합산한다. 과거 ledger에 연결키가 없으면 비용은 null로 남긴다. 실제 50건 시험의 실행별 비용은 별도 pilot 보고서이며 누적 전체 라벨 비용과 구분한다.

상황 요약 생성 API는 이 연결 코드에 포함하지 않는다. 아직 실제 요약 캐시가 없으므로 briefs는 빈 상태다. API 승인과 별도로 전체 라벨 결과·사람 검수·상황 요약 후속 실행이 필요하다.
