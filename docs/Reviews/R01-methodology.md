개인정보나 신고 본문을 출력하지 않고 ZIP을 순차 읽기 및 집계 SQL로 확인했다.

사전 문서의 932,837건은 현재 규칙에 맞는 932,821건과 제품 종류가 비어 있는 16건의 합과 같다. 이는 차이의 설명 후보이며, 사전 코드가 없으므로 과거 구현이 빈 값을 포함했다고 단정하지 않는다. 현재 `PROD_TYPE=V` 규칙을 유지한다. 원본·SQL의 독립 계산이 일치했다.

현대·기아 9개 차종, 접수일 2017-03-01~2019-06-30의 7,433건에서 전화번호 형태가 588건, 딜러 언급이 2,696건 확인되었다. 이메일 형태와 17자리 VIN 형태는 이번 단순 정규식에서 0건이었다. 이것은 **패턴 검출 수**이며 개인정보의 최종 판정이나 부재 보증이 아니다. 부분 VIN, 이름, 주소 등은 별도 검사 대상이다.

## 필수 정확성 수정

### R01-01 / P1 / 설계 수정 확인 — 과거 접수일 재현과 당시 공개 가용성을 구분

**근거:** NHTSA 공식 [CMPL 필드 정의](https://static.nhtsa.gov/odi/ffdd/cmpl/CMPL.txt)는 DATEA를 파일 추가일, LDATE를 NHTSA 접수일로 정의한다. 같은 문서의 2021년 변경 안내는 제조사·차종·부품 이름 등이 변경되어 최신 파일에 반영될 수 있음을 밝힌다. 현재 스냅샷에서 DATEA>LDATE인 신고도 직접 확인되었다.

**위험:** ADR-002의 “사후 지식 없이 얻은 것”과 “그날 알 수 있었던 것만”이라는 표현은 LDATE 필터 테스트의 보장 범위보다 넓다. 공개 파일이 그날 제공되었는지, 이후 정정이 없었는지는 이 테스트로 확인할 수 없다.

**수정:** LDATE 집계는 유지하되 “현재 공개 데이터의 접수일 기준 과거 재현”으로 명시한다. 미래 정보 차단 테스트는 미래 *접수 신고*의 계산 혼입을 검사한다고 한정한다. 요청서의 `작성 가능일`은 월 집계가 완결되는 계산상 날짜이며 실제 역사적 공개·작성 날짜가 아님을 밝힌다. DATEA 추가 제한은 별도 민감도 분석으로 취급한다.

**확인:** ADR-011에 이 한계를 반영했다. 화면·발표의 최종 문구는 각 산출물 검수에서 확인한다.

### R01-02 / P1 / 핵심 수정 확인 — 완료월 및 평가 창 경계의 명시

**근거:** SPEC Step 4는 일 단위 `ldate <= as_of`, Step 6는 월 경보·다음 달 1일의 확인 가능일·마지막 1개월 제외를 함께 사용한다. 월초인 `month`만 cut-off와 비교하면 같은 달 미래 접수 신고가 들어갈 수 있다.

**수정:** 먼저 접수일로 입력을 자른다. 전체/절단 실행의 동등성은 cut-off까지 완결된 월에만 요구한다. 사전 명세를 보존하여 첫 경보 검색과 주 hit의 창은 **접수월** 기준으로 유지하고, `early/late`와 선행 일수만 `available = 경보월 다음 달 1일`로 계산한다. available 기준 창은 별도 민감도 분석으로 남긴다.

**검수 제안의 수정 기록:** 처음에는 available 기준으로 모든 창을 통일하도록 권고했다. 이후 사전 명세의 접수월 창도 미래 정보 혼입을 막는다는 점을 다시 확인했다. 안전을 위해 등록된 주 지표를 바꿀 필요가 없으므로 부모 에이전트의 접수월 기준 보존 결정에 동의했다(ADR-011). 창 변경의 결과를 주 지표로 바꾸지 않았다.

**필수 테스트:**
- 월 중간·월말·다음 달 1일 cut-off, 윤년 2월과 12월→1월.
- 조사일 2020-03-15에서 2020-02월 경보는 `available=2020-03-01`이므로 early. 접수월 기준 주 지표에는 포함되고 available 기준 민감도에는 포함되지 않음.
- 조사일 2020-03-01에서 2020-02월 경보는 선행이 아님.
- 조사일 2020-03-01에서 2019-02월 경보는 접수월 기준 주 창에서는 제외되고, `available=2019-03-01` 기준 민감도 창에서는 포함됨.
- 미래 신고 추가 및 조사 정답 필드 변조가 이전 완료월 경보를 바꾸지 않음.

### R01-03 / P1 / 헬퍼 검증 완료·통합 확인 필요 — 자유서술의 개인정보도 제거

**근거:** ADR-008과 계약은 금지 필드 이름을 검사하지만 본문에 전화번호 형태가 실제로 존재한다. 300~520자 발췌만으로 개인정보가 제거되지는 않는다.

**수정:** LLM 송신 전 본문, 저장되는 라벨 인용·요약, export 본문에 같은 비식별 경계를 둔다. 이메일·전화·전체/부분 VIN·주소·식별 문장 처리를 테스트한다. 일반 정규식만으로 모든 이름을 제거했다고 주장하지 않는다. 공개 전 데모에 실제 보이는 발췌는 별도로 검토한다.

**추가 발견과 수정:** 기준 월 범위 2,143건(2018-10 BOLT 포함)에서 기존 공개 정제 후에도 구조화된 딜러명 exact 문자열이 4건, 도시 exact 문자열이 43건 남았다(5자 이상 단순 대조, 일반 단어의 우연한 일치 가능). 알려진 VIN·도시·딜러명·딜러 전화·딜러 도시·운전자 이름을 로컬 `sensitive_values`로만 읽어 정제하는 헬퍼와 테스트를 추가했다. 개인정보 값은 캐시·API 메타데이터·JSON에 저장하지 않는다.

같은 2,143건에서 표준 패턴 또는 알려진 식별값이 원문에 있는 신고는 411건, 두 방식을 함께 적용한 공개 발췌의 패턴 검출은 **0건**이었다. 367건의 발췌에 식별 문장 생략 표시가 들어갔다. 이는 이번 검출기에서의 검사 결과이며 완전한 익명화 보증이 아니다. `test_privacy.py`: **5 passed**.

### R01-04 / P1 / 미완료 — 사람이 제외한 근거가 AI 요약으로 재진입하지 않음

**근거:** 계약은 `cited ∩ excluded = ∅`만 요구한다. 요청서는 담당자 인용과 `brief_cited`를 합쳐 보여주므로 제외한 신고가 기존 브리프 인용으로 다시 나타날 수 있다.

**수정:** 최종 요청서에서 `excluded ∩ (cited ∪ brief_cited) = ∅`를 강제한다. 브리프가 제외건을 인용하면 브리프를 사용하지 않거나, 남은 근거만으로 재생성한다. 집계가 전체 라벨 건수인지 검토 후 채택 건수인지 각각 표시하여 사람의 제외가 통계 입력을 조용히 바꾸지 않게 한다.

### R01-05 / P1 / 미완료 — 검증률을 정확도·오탐률로 확대 해석하지 않음

**근거:** 선정 대상은 리콜로 이어진 예비조사, 제목으로 지정한 표적 증상, 최소 신고량 등으로 제한된 38개 사례다. 대조는 해당 기간 조사가 없는 차종이며, 실제 안전 문제가 없다고 판정된 차종이 아니다. 대조 선정에는 +12개월 조사 여부도 사용했다.

**수정:** 결과를 “선정된 과거 사례/대조의 표적 경보 발생 비율”로 이름 붙인다. 일반 차량 결함 민감도·정확도·오탐률·리콜 확률을 주장하지 않는다. p값을 안전 문제의 확률로 설명하지 않는다. 100개 차종으로의 업무량 환산은 선정 표본 비율을 단순 확대하는 가정임을 표시한다. 사전 수치와 이번 실행 수치를 출처별로 분리한다.

## 방법론 개선 — 사용자 선택 또는 후속 실험

### R01-06 / P2 — 사례와 대조의 경보 기회가 다름

`cases_pool.yaml`의 38개 사례 중 18개는 여러 차종(최대 6개)에서 표적 경보 하나라도 발생하면 hit다. 대조 36개는 각 한 차종이다. 사례 합산 사전 신고량의 30%보다 작은 대조가 16개다. 이는 낮은 대조 경보율의 한 원인이 될 수 있다.

**이미 SPEC §6에 있는 보조 검증:** 단일 차종 사례 20개와 대응 대조 19개의 비율을 별도로 계산한다. 원래 결과를 삭제하지 않는다.

**새 선택이 필요한 개선:** 차종 수·접수량을 맞춘 대조 재매칭 또는 차종 단위 평가. 재매칭 결과는 기존 holdout 성능을 개선한 것처럼 제시하지 않고 새 실험으로 표시한다.

### R01-07 / P2 — dev/holdout은 조사 단위 분할이며 차종 독립 분할이 아님

다음 차종이 두 split에 걸친다.

| 차종 | dev | holdout |
|---|---|---|
| FORD F-150 | PE16003, PE18008 | PE23001 |
| HYUNDAI SONATA | PE16018, PE19003 | PE18003 |
| HYUNDAI SONATA HYBRID | PE19003 | PE18003 |

특히 SONATA의 인접 조사들은 시간 구간도 가깝다. 서로 독립적인 새 차종에 대한 일반화 성능이라고 말할 수 없다. 기존 split은 유지하고 한계를 표시한다. 차종 연결 성분 단위 split 또는 시간 순서 검증은 다음 실험으로 분리한다. 이미 본 holdout를 재분할해 “처음 적용”이라고 말하지 않는다.

### R01-08 / P2 — 통계·LLM 효과에 관한 주장 범위

- 포아송은 신고량의 계절성, 노출 차량 수 변화, 보도에 따른 신고 증가, 과산포를 직접 모델링하지 않는다. 경보는 검토 후보이며 원인 판정이 아니다.
- 수많은 차종×증상×월 검정을 하므로 개별 p<0.001은 전체 경보의 오류율 보증이 아니다. 전체 증상의 실제 검토 업무량을 함께 보여준다.
- 키워드/LLM primary 일치율은 정확도가 아니다. 사람이 검수한 정답과 비교한 표본에 한해서 정확도라는 이름을 사용하고 표본 수와 선정 방식을 표시한다.
- 현재 LLM의 사전 지식까지 과거 시점으로 되돌릴 수는 없다. 프롬프트와 데이터 절단만으로 “역사적으로 완전히 눈가림된 실험”이라고 주장하지 않는다.

### R01-09 / P1 / 수정 확인 — 사후 평가 마지막 월의 관측 종료

`scoped`는 `ldate < odate+6개월`이지만 첫 경보 검색은 `month <= odate+6개월`이다. 조사일이 3월 15일이면 9월 1일 칸은 9월 14일까지의 부분 자료만으로 계산된다. 월말 경보처럼 평가하면 late/missed 구분이 일부 자료에 기대게 된다. 주 지표에는 영향이 없다.

등록된 수집 범위를 유지하는 최소 수정은 사후 후보의 `available <= 관측 종료일`을 함께 요구하여 미완료 마지막 월을 제외하는 것이다. 또는 수집 범위를 마지막 평가 월 말까지 늘리되 ADR에 변경을 기록한다. 구현 담당과 부모 에이전트에 전달했다.

**확인:** 후보에 `available <= odate+6개월` 조건이 추가되었다. `test_incomplete_last_scope_month_is_excluded`가 미완료 말단월 제외를 검사한다. 관련 백테스트 테스트 **4 passed**를 독립 실행했고, 별도 경계 예제에서 직전 완료월 경보가 유지됨도 확인했다. 구현 담당의 전체 테스트 결과는 **26 passed**, 재출력한 주 지표·대표 선행 일수·사례 분류 변화는 0건이다. P0 계산부 통합에 이견 없음.
