# R08 — 대표 신고 요약·반환 사용량·최종 공개 파일 독립 검수

- 날짜: 2026-10-09
- 범위: 이슈 #12·#17, SPEC Step 8·10, ADR-012·015·024
- 기준 코드: 부모 `codex/llm-evidence-validation`의 `a5c0783`
- 집계 근거: [`data/results/brief_completed.json`](../../data/results/brief_completed.json)
- 판정: **18개 경보 중 16개의 공개 형식·출처 복사 검사 통과, 2개는 실패 상태로 미표시. 정확도 측정 결과가 아니다.**

## 신고별 요약과 캐시

새 `source-summary-selection-v1` 캐시 16개가 선택한 신고별 요약 인용은 총 47개다. 제공된 최대 10개 번호 중 중복 없는 1~3개만 선택했는지 확인했다. 각 줄의 `(#번호) 기존 summary_ko`와 실제 경보 수치로 만든 첫 통계문을 별도로 재구성해 저장 문자열과 대조했으며 불일치는 0개다. 새 단어·상황을 합성하거나 마침표를 바꾸지 않았다.

읽기 전용 DB에서 알려진 식별값만 메모리로 읽은 뒤 연결을 닫았다. 최종 공개 콘솔과 이 식별값으로 입력 해시·프롬프트·모델·선택 모드·캐시 키를 재검증한 `load_validated_briefs` 결과가 공개 `briefs` 16개와 정확히 일치했다. 알려진 식별값을 포함한 입력 경계와 같은 칸·접수월·수량·단정 검사를 통과했다.

구 구조화 자유서술 캐시 1개는 비공개 로컬 캐시에 남아 있지만 새 프롬프트·모드에 맞지 않아 공개 결과에는 0개가 포함됐다. 이 후보는 이전 형식 검사에는 통과했으나 총괄의 제공 요약 대조에서 복합 주장 과장이 확인되어 거부된 결과다(ADR-024). 형식 성공을 의미상 성공으로 바꾸어 기록하지 않았다.

나머지 2개 경보는 각각 최초 선택과 재선택 2회, 총 3회 모두 `unsupported_narrative_number`로 거부됐다. 이 6개 응답의 비용도 원장에 포함된다. 문자를 고치거나 검사 조건을 완화하지 않았으며, 마지막 실행 이후 추가 재시도 없이 두 브리프는 공개하지 않았다.

## 반환 사용량과 비용

모든 78개 브리프 반환 사용량과 5개 실행을 연결했다. 입력 53,567토큰, 출력 4,862토큰, 캐시 입력 0토큰이며 누락 사용량은 없다. 정수 토큰에 기존 기록 요율(입력 $0.40, 캐시 입력 $0.10, 출력 $1.60 / 백만 토큰)을 `Decimal`로 적용했다. 각 응답과 실행 합계의 차이는 부동소수점 표현 오차 범위뿐이며 비용 불일치는 0개다. 요율을 새로 조회한 결과나 청구서 실결제액은 아니다.

초기 자유서술 55개 응답의 거부 이유는 인용 없는 문장 38회, 근거 범위 밖 인용 14회, 수량 2회, 단정 1회다. 새 선택 모드만 집계하면 22개 응답·$0.0071512이며, 성공한 16개 응답은 $0.0051616, 실패한 6개 응답은 $0.0019896이다. 재사용된 1개를 다시 API 응답으로 세지 않았다.

라벨 원장도 다시 십진 계산해 9,996개 반환 응답·**$4.5448836**을 확인했다. 브리프를 포함한 누적 실험 추정 총액은 **$4.5740896**이다. R06의 초기 시험·진단 비용을 제외하지 않았다. 과거 라벨 사용량 10개에는 캐시 키 연결이 없으므로 정확한 현재 라벨 캐시의 1,000건당 비용은 여전히 `null`·미측정이다. 총 실험 비용을 성공 개수로 나누어 정확한 캐시 단가라고 제시하지 않는다.

## 최종 공개 파일

총괄의 최종 export 완료 통보 뒤 `web/public/data`를 읽었다. `completion.json` 포함 JSON 45개가 계약 스키마와 금지 필드 검사를 통과했고, 명세에 실린 payload 44개의 파일 집합과 SHA256이 모두 일치했다. 최종 manifest와 콘솔 해시는 집계 JSON에 보존했다.

- LLM 라벨 7,502건, 공개 신고 2,142건, 근거 셀 421개, 브리프 16개가 manifest·실제 파일과 일치한다.
- 콘솔 신고 원문·요약 및 사례 근거 7,309회에서 나온 공개 문자열 총 18,902개를 현재 이메일 경계 패턴과 신고별 알려진 식별값으로 검사했다. 실패는 0개다. 브리프 16개도 해당 칸 전체 근거의 알려진 식별값으로 검사해 실패 0개다.
- 최종 콘솔은 `briefs` 외에 앞서 검수한 `build/llm-export/console.json`과 완전히 동일하다. KW 38사례 `cases.json`도 stage와 바이트가 같아 기존 주 결과와 실패 사례가 유지된다. R06의 통계 oracle 계산을 중복 수행하지 않았다.
- 개인정보 패턴 변경 뒤 전체 7,502건 라벨 입력 재검증은 총괄의 정상 완료된 export가 수행했다. 이번 독립 검수는 브리프 입력 해시와 최종 공개 결과를 직접 재확인했다.

## 범위와 한계

16/18은 공개 형식·출처 연결 검사 통과 수다. 기존 `summary_ko`가 소비자 원문을 정확히 요약했는지, 선택이 대표성을 갖는지, 분류가 맞는지는 이 결과로 측정하지 않았다. 사람 정답 검수는 사용자 취소로 0건이며 정확도는 미측정이다. 정규식·알려진 식별값 검사는 완전한 비식별화의 증명이 아니다.

검수 중 API 호출·키/환경 파일 읽기·DB 쓰기·원문/개인정보 콘솔 출력은 없었다. 읽기 전용 DB 연결은 식별값 조회 직후 닫았다. 지정된 집계 JSON과 이 검수 문서만 변경한다. 총괄이 export와 병렬로 실행한 테스트의 DB 잠금 실패는 별도 실행 환경 기록이며, 이 검수에서는 잠금 오류가 없었다.
