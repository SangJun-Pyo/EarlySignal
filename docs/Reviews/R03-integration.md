- 날짜: 2026-10-09 (Asia/Seoul)
- 역할: 구현 담당과 분리된 Codex 검수 에이전트
- 범위: 실제 정적 출력 → 시점 선택 → 원문 검토 → 조사 요청서, 상황 요약 검증, LLM 입력·출력 연결 경계
- 상태: 키워드 제품의 코드·출력·순수 함수와 LLM 오프라인 연결 경계 검수 완료. 브라우저 상호작용은 주 에이전트가 별도로 검수한다. 전체 LLM 데이터·의미 품질은 미검증이다.

## R03-01 / P1 / 수정 확인 — AI 요약을 원문 인용으로 저장하지 않음

`request.ts`가 `summary_ko || text`를 인용 문장으로 선택했다. LLM 연결 후에는 AI가 요약한 문장이 원문 발췌를 대체하고 `[담당자 인용]`만 붙어 출처가 불명확해질 수 있었다. 현재 키워드 모드에는 영향이 없었다.

주 에이전트의 수정 위임을 받아 요청서 4번 항목에 **정제 원문 발췌를 항상 유지**했다. 한국어 요약이 있으면 다음 줄에 `AI 요약(담당자 검토 필요)`라고 표시한다. 합성 LLM 테스트에서 원문과 요약이 각각 보존되고 원문 칸에 AI 문장이 들어가지 않는 것을 확인했다.

변경 파일: `web/lib/request.ts`, `web/tests/request.test.ts`. 실제 출력 전체 경보를 통과시키는 `web/tests/export-integration.test.ts`도 추가했다. 이 검사는 다운로드나 브라우저 저장 기능의 E2E 검사를 대신하지 않는다.

## R03-02 / R02 보완 확인 — 상황 요약 숫자의 출처

`brief.py`는 첫 문장을 실제 n·baseline·ratio·streak로 만든 고정 통계문과 정확히 대조하고, 이후 자유 문장의 숫자 표현을 제한한다. 이전의 “다른 지표에 같은 숫자가 있으면 통과”하는 오류를 막는 방향이다. R02의 부상·사망 숫자 혼용 회귀 테스트를 포함한 전체 Python 테스트가 통과했다.

그럼에도 인용 번호가 존재하거나 숫자가 없다는 사실만으로 자유 문장의 의미 정확성이 입증되지는 않는다. 현재 공개 제품의 `briefs={}`는 실제 미생성 상태다. 이를 AI 요약의 품질 검증 완료로 말하지 않는다.

## LLM 연결에 대한 추가 검수 경계

- 50건 승인 범위: limit이 캐시 제외 후 추가 건수이면 재실행 시 50건을 넘길 수 있음을 전달했다. ADR-014의 고정 seed 표본을 먼저 정하고 캐시를 제외하는 수정과 회귀 테스트를 확인했다.
- 호출 제한: Retry-After 초·HTTP 날짜, 60초 이하 공유 대기, 60초 초과 큐 중단, 같은 키·모델의 로컬 재실행 차단, 진행 중 응답 보존, 키·오류 본문 미기록을 합성 테스트로 확인했다. 검수 중 실제 API는 호출하지 않았다.
- 부분 캐시: 실제 캐시 **6/7,502건**으로 읽기 전용 DB와 임시 출력에서 LLM export를 실행해 미완성 오류를 확인했다. 기존 공개 JSON SHA256, DB 테이블 목록, 임시 출력의 기존 marker가 모두 유지됐다.
- 완성 캐시: 합성 데이터 E2E에서 현재 모델·프롬프트·정제 입력 해시를 검사하고, LLM 콘솔이 만들어져도 키워드 주 검증 수치를 바꾸지 않는 것을 확인했다. 이 합성 통과는 실제 전체 라벨 실행이나 정확도를 뜻하지 않는다.
- LLM 연결의 화재·충돌·부상 플래그는 NHTSA 기록과 AI 분류의 합집합이다. `flag_sources`에 이를 표시하고, 요청서에도 출처 설명을 추가했다. UI의 같은 설명은 웹 담당에게 수정 요청했다.
- 실제 사람이 판단한 정답이 없으면 사람 검수 건수는 0, 정확도는 미측정이다. 다른 Codex 에이전트의 검수나 키워드와의 일치율을 사람 정답 검수로 세지 않는다.

## R03-03 / P1 / 수정 확인 — 한국어 조사와 붙은 식별값

LLM 연결 구현 담당이 `Exampleville에서`가 알려진 `Exampleville`과 매칭되지 않는 경우를 발견했다. 기존 Unicode `\w` 경계는 한국어 조사도 단어 내부로 취급했다. 검수 담당이 `privacy.py`를 수정해 Hangul 앞뒤를 식별값 경계로 허용하되 더 긴 영문 이름의 부분 문자열은 차단하지 않도록 했다. `Normalville`과 `Caféville`의 부분어를 오탐하지 않는 회귀도 확인했다. 개인정보 테스트 **6 passed**.

라벨러 담당에게 출력 캐시 저장 전에도 known denylist를 전달하도록 요청했고 `validate_label(..., denied=...)` 반영과 회귀를 확인했다. 오프라인 import에서도 공개 요약·인용문을 다시 검사한다. 이 변경도 모든 고유명사를 찾는다는 보증은 아니다.

## R03-04 / P1 / 수정 확인 — 이전 실행에서 쓴 라벨 비용 누락

초기 LLM export 비용 계산은 최종 성공 캐시의 run_id만 포함했다. 이전 실행에서 응답을 받았으나 검증 실패하고 다음 실행에서 성공한 경우 앞선 유료 응답을 빠뜨릴 수 있었다. 검수 의견에 따라 usage ledger에 cache_key·프롬프트·입력 해시를 넣고, 현재 입력의 cache_key에 연결되는 모든 실행·재시도 응답을 합산하도록 수정했다.

이전 ledger에 연결키가 없거나 사용량을 확인할 수 없으면 전체 단가를 null로 유지한다. 합성 테스트에서 이전 실패 응답과 다음 성공 응답의 비용 합산 및 구 ledger의 null 처리가 통과했다. 실제 6건의 실행별 반환 사용량은 별도 파일에서 보고할 수 있지만, 미완료 표본으로 전체 처리량·정확도를 추정하지 않는다.

## 남은 확인

1. 주 에이전트의 브라우저 저장·다운로드·다시 열기 및 시점 전환 확인.

3. 사람의 정답 라벨 검수와 현업 검토 시간·지속 사용 의향은 별도의 미검증 항목이다.
