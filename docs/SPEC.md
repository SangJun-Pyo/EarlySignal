# EarlySignal — 현재 구현 명세

2026-10-09 공개 제품과 검수 결과를 기준으로 정리했다. 구현 절차는 [WORKFLOW](Development/WORKFLOW.md), 데이터 형식은 [계약](Contracts/data-contract-v1.md), 실제 결과와 실행 명령은 [README](../README.md)를 따른다. 사전 설계·시제품 수치·당일 목표 시각은 [이전 SPEC 원본](history/SPEC-v2-before-current-state-2026-10-09.md)에 보존한다. 이 문서의 완료 표시는 제품·산출물 검증이며 현업 효과나 분류 정확도 검증을 뜻하지 않는다.

## 0. 제품과 현재 범위

**고객의 목소리를, 조사의 근거로.** 자동차 회사의 고객 안전 담당자가 소비자 신고에서 조사할 후보를 찾고, 원문을 검토해 조사 요청서를 저장하는 도구다. LLM은 신고를 라벨·요약으로 측정하고, 통계는 평소보다 이례적인 증가인지 판단하며, 사람은 조사 착수·보류·기각을 결정한다.

공개 제품은 **신고 원문 → 신호와 근거 → 조사 요청서**의 세 단계와 보조 검증 결과 화면으로 구성된다. 요청서 저장·Markdown 다운로드·결정 이력 JSON 다운로드는 브라우저에서 처리한다. `made`는 실제 저장 시각이고 과거 데이터의 `analysis_available`은 분석 가능일이다. 두 날짜를 분리한다.

| 항목 | 현재 구현·실측 |
|---|---|
| 분류 대상 | 현대·기아 9개 차종과 볼트 EV의 고정 데모 범위 7,502건, LLM 출력 검사 완료 |
| 공개 콘솔 | 현대·기아 9개 차종, 2018-03~10 접수월, 기본 2018-08 |
| 데모 신호 | HYUNDAI SONATA·화재/과열·2018-08, 17건·직전12개월 평균59/12=4.9167건·3.46배 |
| 공개 파일 | JSON45개, 콘솔 신고2,142건·근거421칸·대표 신고 요약16개 |

## 2. 저장소와 데이터

- `pipeline/es/`: 적재·분류·탐지·평가·내보내기. 구현 파일은 `ingest`, `scope`, `label_kw`, `label_llm`, `import_llm`, `aggregate`, `detect`, `backtest`, `export`, `export_llm`, `brief`, `human_review`, `privacy`, `cli`다. `forecast.py`는 없다.
- `web/`: Next.js 정적 제품. `lib/request.ts`는 화면·Markdown 공통 요청서 생성 함수, `lib/asof.ts`는 기준월 자르기 함수다.
- `web/public/data/`: 검수한 공개 JSON을 커밋한다. API 없이 제품을 실행한다.
- `data/raw/`, `data/*.duckdb`, `data/labels/`, `data/private/`, `.env`: 로컬 자료이며 커밋하지 않는다. 라벨·요약 캐시는 일반 clone에 포함되지 않는다.
- `docs/ADR`, `docs/Sessions`, `docs/Reviews`: 당시 결정·실행·검수 기록이다. 현재 상태는 README와 [STATUS](Development/STATUS.md)를 우선 확인한다.

NHTSA 신고는 UTF-8·탭 구분·헤더 없는51컬럼, 조사 파일은11컬럼이다. 적재는 따옴표 해석을 끄고 파싱 결과를 기록한다. 데이터 URL·다운로드 파일과 해시는 [출처 manifest](../data/results/source_manifest.json)에 있다. 모든 현재 수치는 그 입력을 사용한 실행 결과이며 이후 NHTSA 파일 교체 시 달라질 수 있다.

## 3. 파이프라인 단계와 완료 근거

### Step 1. 적재

소비자 유형과 `PROD_TYPE='V'`를 필터링하고 `ODINO` 고유 신고로 합친다. 집계 날짜는 `LDATE` 접수일이다. `FAILDATE`, 사후 부품 분류와 조사 요약은 탐지 입력으로 쓰지 않는다. 원본1,301,663행에서 고유 소비자 차량 신고932,821건을 적재했고 접수일 파싱 실패0건이다. 사전 시제품932,837건과의 차이는 [S06](Sessions/S06-step6.md)·[R01](Reviews/R01-methodology.md)에 남겨 두며 결과를 맞추기 위해 규칙을 바꾸지 않았다.

### Step 2. 범위

감시 단위는 연식을 합친 `MAKE|MODEL`이다. 등록 사례·대조군의 조사일−48개월~+6개월 범위 `scoped`는122,989건이다. 별도 `demo`는7,502건이다.

- 현대 SANTA FE·SANTA FE SPORT·SONATA·SONATA HYBRID와 기아 OPTIMA·OPTIMA HYBRID·SORENTO·SOUL·SOUL EV: 접수일2017-03-01 이상2019-07-01 미만.
- CHEVROLET BOLT EV: 접수일2018-10-01 이상2021-02-01 미만.

콘솔은 이 중 현대·기아9개 차종의2018-03~10 신고를 보여준다. 볼트는 사후 비교 자료에 포함한다. 전체 등록38사례 평가창과 LLM 데모 관측창은 다르다.

### Step 3. 키워드 기준선

`config.CATEGORIES`의16개 증상 중 primary1개·secondary최대2개를 우선순위 정규식으로 정한다. `scoped`와 `demo` 모두 `labels_kw`로 저장한다. 기준선은 LLM의 정답이 아니다. 코드·패턴과 등록평가 결과를 보존하고 holdout을 보고 조정하지 않는다.

### Step 4. 집계

차종×증상×접수월별 고유 신고 수를 센다. primary와 secondary를 모두 반영하며 신고 없는 달은0으로 채운다. 차종별 전체 신고 수는 별도 분모다. `--as-of`가 있으면 그 날짜까지 접수된 신고만 쓴다.

### Step 5. 탐지

현재 월을 뺀 직전12개월 평균을 λ로 쓰며 이력이6개월 미만이면 판단하지 않는다. λ하한은0.5다. `P(X≥현재건수 | Poisson(λ)) < 0.001`이고 월3건 이상이면 경보다. 이항 검정은 비교 분석이며 주 경보 규칙이 아니다. 포아송 독립성·평균 안정성·과산포 등의 분포 가정을 실제로 검증했다는 주장은 하지 않는다.

### Step 6. 등록 백테스트·미래 정보 차단

주 평가는 **키워드**38사례·36대조다. 사전 dev에서 정한 규칙을 holdout에 적용하며 조사 전12개월의 접수월 창에서 마지막1개월을 제외한 표적 경보 여부를 비교한다. 첫 경보·early/late/missed는 별도의 넓은 관측창에서 구하므로 주 비율과 혼동하지 않는다.

| 분할 | 사례 | 대조 |
|---|---:|---:|
| dev | 9/19 | 0/19 |
| holdout | 7/19 | 1/17 |

[backtest_kw.json](../data/backtest_kw.json)에 놓친·늦은 사례를 보존한다. 차종1개 사례로 제한한 보조 분석은8/20, 대조1/19다. 주 평가의 여러 차종 사례/단일 차종 대조, 낮은 대조 신고량·분할 간 차종 중복은 한계다.

38회 기준일 재계산(고유날짜33개)과 독립64칸 계산 일치는 [lookahead_kw.json](../data/results/lookahead_kw.json)·R01에 기록됐다. 계산상의 미래 접수를 차단한 검증이며 당시 NHTSA 파일의 공개·수정 이력 복원이나 모형 적합성 검증은 아니다.

209·240일은 지정 PE19003·PE19004의2019-03-29 개시일과 비교한 값이다. 그 전에2018-06-11 청원·08-21 청원 검토 및 기존 리콜 조사가 있었다. 기관 최초 인지·최초 조사나 AI 최초 발견을 뜻하지 않는다([ADR-025](ADR/ADR-025-designated-pe-comparison-context.md)). 키워드 볼트 EV는 놓쳤고 같은 LLM 데모 비교도23일 늦었다.

### Step 7. LLM 라벨·출력 검사

현재 모델은 `gpt-4.1-mini-2025-04-14`다. 원문을 정제해 최대1,500자로 보내며 Chat Completions의 strict JSON Schema, temperature0을 사용한다.16개 증상 중 주1개·보조최대2개, 상황·심각도·한국어 요약·원문 근거를 만든다. 프롬프트와 검사 기준은 [LLM_PROMPTS](LLM_PROMPTS.md)·ADR-018·024를 따른다.

초기50건 시험과 인용 실패14건 개선 후 전체 실행을 완료했다. 원문 인용 실패 시 분류 필드를 바꾸지 않고 실제 원문 후보를 선택한다. 현재 입력·모델·프롬프트/스키마 해시가 맞는7,502건 캐시를 검사했으며 스키마·인용/개인정보 검사 실패0건이다. 이전 실행 실패·진단은 지우지 않는다([R06](Reviews/R06-full-llm-audit.md)).

동일7,502건의 주 증상 일치는3,793건(50.56%)이며 정확도가 아니다. 개발60건 비교는27/60이다. 독립30건 검수 자료를 준비했지만 사용자가 전문성·시간 제약으로 검수를 중단했다. 사람 정답0건·정확도미측정을 유지하며 AI로 정답을 대신하지 않는다.

### Step 8. 공개 내보내기

`export --method llm`은 전체 현재 입력의 라벨 완전성을 먼저 확인한다. 누락·오래된 캐시가 있으면 실패하며 LLM 요청을 키워드로 자동 대체하지 않는다. 키워드 모드는 명시적으로 별도 내보낼 수 있다.

- `meta.json`: 출처·규칙·키워드 주 평가·업무량·LLM 출력 수. 사람 정답과 정확한 캐시 단가는 미측정(`null`).
- `console.json`: 기본월2018-08,8개 기준월·9개 차종·주요9개 증상, 월별 series·snapshots·원문·근거·요약·사후 비교. 현재 forecast 필드는 없다.
- `cases.json`, `cases/{id}.json`:38개 키워드 사례 요약·상세와36대조.
- `cases_llm/{PE19003|PE19004|PE20016}.json`:3개 LLM 사후 비교 상세. `coverage.registered_window_complete=false`이며 주38사례 비율을 대체하지 않는다.
- `completion.json`:44개 데이터 파일의 해시·건수·완료 상태. 자신을 포함한 공개 JSON은45개다.

콘솔 series는 마지막 제공월까지만 담고 화면에서 선택한 기준월까지 자른다. 이후 실제값은 사후 비교에만 쓴다. 모든 공개 원문은 식별정보를 검사·가리고 길이를 제한한다. 근거칸은 신고3건 이상이며 `evidence.ids`는 해당 신고 전체, 모델에 제공하는 후보는 최대10건이다. 계약·인용·개인정보 테스트를 함께 통과해야 한다.

### Step 9. 웹 제품과 배포

IBM Plex Sans KR·어두운 남색 업무 화면·Recharts를 사용한다. 수치·차종은 공개JSON에서 읽고 디자인 시안 수치를 사용하지 않는다.

1. **신고 원문**: 기준월 접수 원문·표현을 확인한다.
2. **신호와 근거**: 기준월 선택, 차종×증상 히트맵·경보, 발생 상황 집계·대표 신고 요약·원문을 검토한다. 상황별 필터와 원문 인용·제외를 적용한다. 월별 추이는 기준월까지만 보여준다.
3. **조사 요청서**: 실제 통계·반복 상황·대표 신고 요약·인용/제외 신고·미확인 사항·내부 확인 항목·담당자 판단의7항목을 만든다. 착수/보류/기각, 다음 조치, 메모를 입력해 저장한다. 저장일은 실제 시각이며 분석 가능일과 다르다. Markdown·결정 이력JSON 다운로드, localStorage저장 실패 처리를 지원한다.
4. **검증 결과**:38사례 키워드 주 결과·대조·실패, 방법과 한계를 확인한다. 지정PE 사후 비교는 현재 판단과 구분한다.

Next.js 정적 `web/out`을 Cloudflare Pages가 GitHub main에서 빌드·게시한다. 브라우저는 상대 경로JSON을 읽고 배포 환경에는 OpenAI 키를 넣지 않는다. [실제 배포 검수](../data/results/deployment_llm_verification.json)는45개JSON의 바이트 해시·요청서 저장·다운로드 확인을 기록한다. 추가 웹 문구 변경 후 배포 검수는 해당 세션에 따로 기록한다.

### Step 10. 대표 신고 선택과 기존 요약 인용

ADR-024에 따라 모델은 같은 경보칸의 제공된 최대10개 신고에서 중복 없는 번호1~3개만 선택한다. 새 종합 문장을 만들지 않는다. 프로그램이 실제 통계문 뒤에 기존 `summary_ko`를 `(#번호) 기존 요약`으로 그대로 연결한다. 같은 칸·월·번호·수량·개인정보·단정 검사와 캐시 재구성 일치가 필요하다. 최초 선택 뒤 재선택은최대2회이며 끝내 통과하지 못하면 요약 없이 근거를 제공한다.

현재18개 대상 중16개 공개·2개 거부다. 자유 종합54응답0/18, 구조화 첫1개 형식 통과 후 의미 과장으로 공개 거부, 기존 요약 선택으로 바꾼 이력을 [R08](Reviews/R08-brief-completion.md)에 남겼다. 원문 의미 정확도·대표성·공통 원인은 검증하지 않았으며 담당자가 원문을 대조한다.
