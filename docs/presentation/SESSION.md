# 발표 자료 작업 기록

- 날짜: 2026-10-09 (Asia/Seoul)
- 범위: `docs/presentation/`. 공유 코드·ADR·제품 데이터는 이 작업에서 수정하지 않았다.
- 역할: 최초 발표 제작 에이전트가 초안을 만들고, 총괄이 실측 연결을 추가했으며, 후속 발표 에이전트가 실제 화면·8분 결선 구성·전체 검수까지 마무리했다.
- 최신 상태: 전체 LLM 출력·공개 배포·시연 실측을 반영한 발표자료. 사람 정답 기반 정확도 검수·발표 리허설은 미완료다. 아래 기록은 각 시점의 이력을 보존한다.

## 사용자 결정

1. 핵심 제품 흐름은 경보 선택 → 원문 검토 → 요청서 저장이다.
2. 주장별 근거·실패·미검증 가정과 Codex 독립 검수 기록을 보완한다.
3. 일반 심사위원을 위해 자동차 회사에서 고객 안전을 살피는 담당자를 주인공으로 삼는다.
4. 예선 4분과 결선 자료를 모두 만들고, 결선은 8분 발표·데모 + 2분 질의응답으로 구성한다. 자세한 검증은 부록으로 둔다.
5. 모델은 50건 시험 후 비용을 보고 전체 실행을 결정한다. 발표에도 이 경계를 유지한다.

## 계획과 구현

PDF 제작과 사용자 문체 스킬을 읽고 적용했다. 문체 자료 검색은 관련 발표를 찾는 한 번의 제한된 검색으로 진행했으나 관련 없는 결과만 나와 사용하지 않았다. 내부 기록: “No suitable writing references found in the returned results.” 현재 사용자 요청의 간단하고 직접적인 한국어와 비전문가 청중 조건을 우선했다.

ReportLab 소스를 유지하며 총괄이 연결한 `meta.json`, `cases.json`, 미래 접수 차단 실측을 보존했다. 실제 저장 결과인 `assets/screenshots/request-desktop.jpg`의 요청서·판단·저장 영역을 PDF에 확대 배치했다. 이미지 원본은 변경하지 않았다.

- 예선: 9장, 발표·데모 합계 240초.
- 결선: 본문 12장, 발표·데모 480초 + 질의응답 120초. PDF 뒤에 검증 부록 4장, 총 16장.
- 결선 본문 끝에 Q&A 전환을 표시하고, 부록 페이지 번호를 별도로 붙였다.
- 현재 키워드 제품과 AI 시험 6/50 성공 상태를 구분했다. 상황 요약이 비어 있는 이유도 설명한다.
- 사전 결과와 다른 dev 9/19 및 볼트 missed를 유지했다. 정확도·오탐률·사고 예방 효과로 바꾸어 말하지 않는다.
- 일부 AI 사용량 비용은 근거표·질의응답 노트에 해당 실행 범위를 명시했다. 불완전한 표본의 전체 비용·처리량 추정은 PDF에 넣지 않았다.

## 생성과 검수

PDF 편집 시작 직전에 PDF 스킬의 `mark_artifact_operation_started.mjs --operation-kind edit --expected-output-count 2 --output-format pdf`를 한 번 실행했다.

```bash
python docs/presentation/build_decks.py
pdftoppm -scale-to 1280 -png docs/presentation/output/pdf/EarlySignal-preliminary-4min-DRAFT.pdf docs/presentation/tmp/pdfs/final-review/preliminary
pdftoppm -scale-to 1280 -png docs/presentation/output/pdf/EarlySignal-finals-10min-DRAFT.pdf docs/presentation/tmp/pdfs/final-review/finals
```

- 예선 9페이지·결선 16페이지, 모든 페이지 1280×720pt 확인.
- 시간 합계 240초와 480초, 결선 Q&A 120초를 생성 코드에서 검사.
- 모든 페이지에 DRAFT 표시, 실측 핵심 값과 실패 사례 포함 확인.
- 추출된 모든 본문 문자의 Regular/SemiBold 글리프 누락 0.
- 25페이지를 모두 렌더링해 시각 검수. 한글 깨짐·텍스트 겹침·박스 잘림을 발견하지 않았다. 화면 이미지는 전체 요청서를 작게 읽는 용도가 아니라 실제 시연으로 전환할 증거 캡처다.
- 출처 JSON·검수 문서·캡처와 최종 PDF의 SHA256을 `qa.json`에 남겼다.
- 실제 발표 리허설, 녹화, 최종 배포 시연은 수행하지 않았다.

## 독립 검수와 수정

발표 작성자와 다른 `/root/independent_review`에 PDF·storyboard·실측 원본의 대조를 요청했다. 독립 검수에서 실측 값과 시간 합계는 일치했고 다음 표현·메타 보완을 요청했다.

| 발견 | 반영 |
|---|---|
| “38개 기준일”은 서로 다른 날짜 38개처럼 보임 | “38개 조사 사례의 기준일”로 수정. 실행 38건, 고유 cutoff 33개를 노트에 구분 |
| 첫 경보는 사후 late 검색도 포함하는데 부록이 “조사 전”만 설명 | “공식 조사 전후 정해진 기간”으로 수정 |
| 209일·240일이 무엇보다 먼저인지 본문에 불명확 | 공식 조사 개시 대비 선행 일수라고 결과 장에 표시 |
| “사람이 고친 내용”이 실제 Codex 수정과 혼동 | 사용자 선택과 Codex 구현·독립 검수 결과로 구분 |

수정 뒤 두 PDF 전체를 다시 렌더링하고 영향을 받은 6페이지를 재검수했다. 독립 검수자도 최신 PDF 텍스트를 재추출해 수정 반영을 확인했고 추가 차단 사항이 없다고 보고했다. `qa.json`·노트·근거표·README를 같은 상태로 맞췄다. 최종 PDF에는 현업 효과를 확인한 것처럼 표현하지 않는다.

커밋과 푸시는 하지 않았다. `docs/CODEX_LOG.md`·ADR-010의 8분+2분 결정·Step 통합 커밋은 총괄이 관리한다. 모델 시험 상태 또는 배포 URL이 바뀌면 관련 문구와 QA 출처 해시를 다시 갱신해야 한다.

## 2026-10-09 후속: 통계·LLM 분류·기획 대조 보강

사용자는 월별 집계와 포아송을 본문 두 장으로 설명하고 사용하는 검증 통계, LLM 데이터 분류, pgvector/RAG의 범위를 모두 담도록 요청했다. 현재 pgvector/RAG 미사용 상태를 확인한 뒤 **분류 검증 우선 + RAG 근거 검색 보완 설계**를 선택했다. ADR-016을 먼저 작성했고, 총괄이 기록한 제출 기획 대조 ADR-017을 발표에 연결했다. 실제 API나 벡터 DB 추가 구현은 하지 않았다.

PDF 편집 시작 직전에 PDF 스킬의 `mark_artifact_operation_started.mjs --operation-kind edit --expected-output-count 2 --output-format pdf`를 이번 편집 작업에 한 번 실행했다. PDF·사용자 문체 스킬을 적용했다. 기존의 적합한 문체 참고 검색 결과가 없다는 기록을 재사용하고, 사용자의 비전문가 대상 직접적인 한국어 요청을 따른다.

- 예선은 본문 12장/240초, 시간 외 부록 6장으로 총 18페이지다.
- 결선은 같은 본문 12장/480초 + 120초 질의응답, 시간 외 부록 9장으로 총 21페이지다.
- 본문 5·6장은 실제 월별 82/12→17건과 포아송 p=.0007412096을 각각 설명한다. 그래프 담당자가 현재 공개 JSON과 탐지 코드로 그림·출처 수치를 만들고 독립 합산을 확인했다.
- 본문 4장은 직접 LLM 분류와 출력 검사, 7장은 dev/holdout과 대조, 8장은 38회 미래 접수 차단과 64칸 독립 검산을 보여준다. 검사 종류를 모형 적합성이나 사람 정답 정확도와 혼동하지 않는다.
- 이항 비교 계산, 관측 차종월당 경보량, 단일 차종 보조 분석을 부록으로 포함했다. 주 경보 규칙은 변경하지 않았다.
- 최신 고정 AI 시험은 총 36/50 출력 검사 통과, 14건 인용 검사 실패를 반영했다. 재개 실행 완료 30건과 기존 성공 캐시 6건을 구분해 cohort 필드를 우선 사용한다.
- 공개 배포 제품의 2026-10-09 11:13:23 KST 실제 확정·저장 캡처로 교체했다. 원본 이미지를 수정하지 않고 PDF 표시 영역을 사용했다.
- pgvector/RAG 미구현·평가 지표 미측정과 원래 기획의 유사 사례 기능 보완이라는 사실을 부록에 명시했다. 별도 부품 추출 미구현, 고정 코드 분류, KW 임시 기준선, 요청서=담당자 결정 구체화를 대조표에 담았다.

최종 39페이지를 1280px PNG로 렌더링하고 전체를 시각 검수했다. 새 그래프·계산·RAG·기획 대조 페이지는 개별로 추가 확인했다. 최초 렌더에서 그리스문자 글리프 누락과 검증 순서 패널의 어색한 줄바꿈을 찾아 수정했다. 마지막 PDF 텍스트의 Regular/SemiBold 글리프 누락은 0이다. 모든 페이지의 크기 1280×720, DRAFT 표시, 본문 240초/480초 합계와 주 통계 본문 2장 포함을 검사했다. 해시는 `qa.json`에 기록했다.

작성자와 다른 `brief_finish`가 ADR-017 원안과 발표 대조표의 정합성을 확인했다. 통계 개정본의 전체 독립 검수는 총괄이 배정하며 발견 사항은 후속 기록한다. 실제 시간 리허설과 장애 대비 녹화는 미완료다. 커밋·푸시는 하지 않았다.

독립 검수 후속: `brief_finish`가 최신 18+21페이지 전체 텍스트와 핵심 5·6·7·18페이지 렌더를 검수했다. 월별·평균·배수·포아송 독립 합산, 사례/대조 비율·선행일·볼트 놓침·업무량·민감도 수치가 일치했다. 노트의 부록 수·페이지와 근거표 E19–E24/시험/캡처 상태 동기화 지적은 수정 후 재확인했다. 근거표의 빈 줄도 제거해 동일 표로 연결했다. 추가 주요 오류는 없었다.

## 후속: 50건 출력 검사 완료와 조사 가설 설계

사용자는 현재 제품을 먼저 완성하고 조사 가설·확인 절차는 설계와 발표에만 추가하도록 선택했다. ADR-019/S17을 읽고, 실제 현대·기아 원인을 추정한 예시 없이 `원문에 명시된 증상 → 조사 질문·대안 설명 → 필요한 정비·검사·작업·생산 자료 → 담당자 확인`을 공통 부록 7에 추가했다. 자료는 아직 미연결이며 가설 생성과 확인도 미구현이다. 근거 부족이면 보류하고 확률을 붙이지 않는 범위를 명시했다.

고정 AI 표본은 50/50 API 출력 검사 통과로 갱신했다. 본문 4장에 이 숫자가 분류 정확도가 아니며, 38개 조사 사례 통계 백테스트와 별개이고 사람 정답 기반 분류 정확도는 미측정이라고 함께 표시했다. 초기 인용 실패 14건이 원문 후보 번호 재선택으로 해결된 사실을 부록과 근거표에 유지했다. 전체 후보 7,502건은 아직 미실행이며 비용 보고 후 사용자가 결정한다.

이번 추가 편집 직전 PDF 작업 시작 표식을 2개 출력 대상으로 한 번 실행했다. 예선 본문 12장/240초 + 부록 7장=19페이지, 결선 본문 12장/480초 + 부록 10장=22페이지로 총 41페이지를 렌더링했다. 변경된 분류·현재범위·기획대조·가설 페이지를 개별 시각 검수했고 글리프 누락 0, 시간 합계 유지, 원인 추정 결과와 정확도 수치를 만들지 않았음을 확인했다. 변하지 않은 나머지 페이지는 앞선 전체 검수 결과를 유지한다. 결선 제품 설명 100초 안에서 10초만 후속 설계 설명에 쓰며 예선 본문에는 추가하지 않는다. 실제 타이머 리허설은 미완료다.

비용 전체 합계는 총괄의 원장 검산을 기다리며 본문에 불완전한 비용 추정을 추가하지 않았다. 최신 PDF·출처 해시는 `qa.json`에 반영했다. 추가 코드·API·DB 구현, 커밋·푸시는 하지 않았다.

후속 독립 검수: `brief_finish`가 두 PDF 4·16·19장의 최종 텍스트를 확인해 50/50 출력 검사와 사람 정확도·38사례 백테스트의 구분, 14건 인용 후보 선택, 전체 실행 결과 대기, 후속 가설 설계의 경계가 적절하다고 확인했다. “확인된 신고 내용”은 사실 확인으로 읽힐 수 있다는 제안에 따라 “원문에 명시된 내용”으로 바꿨다.
