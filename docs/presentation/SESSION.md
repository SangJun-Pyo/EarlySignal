# 발표 자료 작업 기록

- 날짜: 2026-10-09 (Asia/Seoul)
- 범위: `docs/presentation/`. 공유 코드·ADR·제품 데이터는 이 작업에서 수정하지 않았다.
- 역할: 최초 발표 제작 에이전트가 초안을 만들고, 총괄이 실측 연결을 추가했으며, 후속 발표 에이전트가 실제 화면·8분 결선 구성·전체 검수까지 마무리했다.
- 상태: 실측 반영 검토본 완료. AI 시험·사람 정답·배포 환경 시연·발표 리허설은 별도 미완료 항목이다.

## 사용자 결정

1. 핵심 제품 흐름은 경보 선택 → 원문 검토 → 요청서 저장이다.
2. 주장별 근거·실패·미검증 가정과 Codex 독립 검수 기록을 보완한다.
3. 일반 심사위원을 위해 자동차 회사에서 고객 안전을 살피는 담당자를 주인공으로 삼는다.
4. 예선 4분과 결선 자료를 모두 만들고, 결선은 8분 발표·데모 + 2분 질의응답으로 구성한다. 자세한 검증은 부록으로 둔다.
5. 모델은 50건 시험 후 비용을 보고 전체 실행을 결정한다. 발표에도 이 경계를 유지한다.

## 계획과 구현

PDF 제작과 사용자 문체 스킬을 읽고 적용했다. 문체 자료 검색은 관련 발표를 찾는 한 번의 제한된 검색으로 진행했으나 관련 없는 결과만 나와 사용하지 않았다. 내부 기록: “No suitable writing references found in the returned results.” 현재 사용자 요청의 간단하고 직접적인 한국어와 비전문가 청중 조건을 우선했다.

ReportLab 소스를 유지하며 총괄이 연결한 `meta.json`, `cases.json`, 미래 접수 차단 실측을 보존했다. 실제 저장 결과인 `assets/screenshots/request-desktop.jpg`의 요청서·판단·저장 영역을 PDF에 확대 배치했다. 이미지 원본은 변경하지 않았다.

- 예선: 9장, 발표·데모 합계 240초.
- 결선: 본문 12장, 발표·데모 480초 + 질의응답 120초. PDF 뒤에 검증 부록 4장, 총 16장.
- 결선 본문 끝에 Q&A 전환을 표시하고, 부록 페이지 번호를 별도로 붙였다.
- 현재 키워드 제품과 AI 시험 6/50 성공 상태를 구분했다. 상황 요약이 비어 있는 이유도 설명한다.
- 사전 결과와 다른 dev 9/19 및 볼트 missed를 유지했다. 정확도·오탐률·사고 예방 효과로 바꾸어 말하지 않는다.
- 일부 AI 사용량 비용은 근거표·질의응답 노트에 해당 실행 범위를 명시했다. 불완전한 표본의 전체 비용·처리량 추정은 PDF에 넣지 않았다.

## 생성과 검수

PDF 편집 시작 직전에 PDF 스킬의 `mark_artifact_operation_started.mjs --operation-kind edit --expected-output-count 2 --output-format pdf`를 한 번 실행했다.

```bash
python docs/presentation/build_decks.py
pdftoppm -scale-to 1280 -png docs/presentation/output/pdf/EarlySignal-preliminary-4min-DRAFT.pdf docs/presentation/tmp/pdfs/final-review/preliminary
pdftoppm -scale-to 1280 -png docs/presentation/output/pdf/EarlySignal-finals-10min-DRAFT.pdf docs/presentation/tmp/pdfs/final-review/finals
```

- 예선 9페이지·결선 16페이지, 모든 페이지 1280×720pt 확인.
- 시간 합계 240초와 480초, 결선 Q&A 120초를 생성 코드에서 검사.
- 모든 페이지에 DRAFT 표시, 실측 핵심 값과 실패 사례 포함 확인.
- 추출된 모든 본문 문자의 Regular/SemiBold 글리프 누락 0.
- 25페이지를 모두 렌더링해 시각 검수. 한글 깨짐·텍스트 겹침·박스 잘림을 발견하지 않았다. 화면 이미지는 전체 요청서를 작게 읽는 용도가 아니라 실제 시연으로 전환할 증거 캡처다.
- 출처 JSON·검수 문서·캡처와 최종 PDF의 SHA256을 `qa.json`에 남겼다.
- 실제 발표 리허설, 녹화, 최종 배포 시연은 수행하지 않았다.

## 독립 검수와 수정

발표 작성자와 다른 `/root/independent_review`에 PDF·storyboard·실측 원본의 대조를 요청했다. 독립 검수에서 실측 값과 시간 합계는 일치했고 다음 표현·메타 보완을 요청했다.

| 발견 | 반영 |
|---|---|
| “38개 기준일”은 서로 다른 날짜 38개처럼 보임 | “38개 조사 사례의 기준일”로 수정. 실행 38건, 고유 cutoff 33개를 노트에 구분 |
| 첫 경보는 사후 late 검색도 포함하는데 부록이 “조사 전”만 설명 | “공식 조사 전후 정해진 기간”으로 수정 |
| 209일·240일이 무엇보다 먼저인지 본문에 불명확 | 공식 조사 개시 대비 선행 일수라고 결과 장에 표시 |
| “사람이 고친 내용”이 실제 Codex 수정과 혼동 | 사용자 선택과 Codex 구현·독립 검수 결과로 구분 |
| storyboard의 결과 takeaway가 재현 대기로 남음 | PDF의 실측 결과 설명과 동일하게 갱신 |

수정 뒤 두 PDF 전체를 다시 렌더링하고 영향을 받은 6페이지를 재검수했다. 독립 검수자도 최신 PDF 텍스트를 재추출해 수정 반영을 확인했고 추가 차단 사항이 없다고 보고했다. `qa.json`·노트·근거표·README를 같은 상태로 맞췄다. 최종 PDF에는 현업 효과를 확인한 것처럼 표현하지 않는다.
