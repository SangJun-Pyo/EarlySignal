# 발표자 노트 · 통계와 LLM 분류 설명 보강

예선은 **본문 12장, 240초**다. 월별 기준선과 포아송 경보를 서로 다른 본문 두 장으로 설명한다. 상세 계산·검증 프로토콜·분류/상황 요약·pgvector/RAG 설계는 시간 외 부록 7장에 둔다. 결선은 같은 본문 12장을 480초에 설명하고, 120초 질의응답에서 부록 10장을 필요에 따라 연다. 이 시간은 배분안이며 실제 리허설 완료 기록이 아니다.

현재 제품은 **키워드 기준선**이다. 고정 신고 50건 모두 API 출력 검사를 통과했다. 초기 인용 실패 14건은 같은 원문의 후보 번호 재선택으로 해결했다. **50/50은 분류 정확도가 아니다.** 신고가 스키마·인용·식별정보 검사 조건을 충족한 수다. **38개 조사 사례는 별도의 통계 백테스트 대상**이며, **사람 정답 기반 분류 정확도는 미측정**이다. 전체 후보 7,502건과 데모 상황 요약의 추가 실행이 승인됐으며 결과를 기다린다. 현재 PDF는 고정 50건 시험 완료 시점의 중간 검토본이다.

## 통계 질의응답

- **포아송 p값:** 모형을 가정했을 때 관측 건수 이상이 나올 상위 꼬리 확률이다. 해당 차종의 결함 확률, 일반 오탐률, 전체 오류율이 아니다. 독립·동일 발생률·평균과 분산 동일이라는 가정의 적합성은 검증하지 않았다.
- **월별 기준선:** 직전 12개월(당월 제외, 0건 월 포함), 최소 6개월 이력, 평균 하한 0.5. 실제 예시는 82/12=6.833333이며 17건의 p=0.0007412096이다. 막대그림은 실제 건수, 확률그림은 이 평균을 가정한 이론 모형이다.
- **이항 비교:** 직전 기간 전체 신고 중 해당 증상의 비율을 기준으로 이번 달 전체 신고 중 비율 증가를 계산한다. 코드에서 비교용으로 계산하지만 현재 제품의 주 경보와 주 평가에는 포아송만 사용한다. 발표를 위해 규칙을 바꾸지 않았다.
- **주 지표:** 경보 접수월 m이 조사일−12개월 이상, 조사일−1개월 미만인 범위에서 표적 범주의 경보가 발생한 사례 비율이다. 사례는 여러 차종 묶음일 수 있고 대조는 단일 차종이다.
- **선행 일수:** 경보 접수월 다음 달 첫날과 공식 조사 개시일의 차이다. 실제 당시 운영·조사 착수·사고 예방 효과가 아니다. 사후 늦은 경보 검색에도 완료월 제약을 적용한다.
- **38회·64칸:** 38개 조사 사례(고유 cutoff 33개)의 완료월 재계산과 64개 표본 칸의 기준선·확률·경보 독립 검산은 서로 다른 검사다. 둘 다 의미 정확도나 분포 적합성 검사가 아니다.
- **대조군:** 해당 기간 조사 기록이 없던 차종이다. 문제가 전혀 없다는 음성 정답이 아니며 작은 신고량·차종 중복 한계가 있다.
- **업무량:** 0.199와 0.092는 등록 평가창의 차종·월당 증상별 경보 수다. 전사 월간 경보 총수나 현업 검토 시간으로 환산하지 않는다.
- **민감도 분석:** 단일 차종 사례 8/20·대조 1/19를 별도 보고한다. 주 분석과 합치거나 유리한 결과로 교체하지 않는다.

## AI와 검색 질의응답

- **분류:** 16개 증상 중 주 라벨 1개와 보조 최대 2개, 위험 요소 6개, 심각도 1~3, 원문 인용과 한국어 요약을 출력한다. 인용은 송신 원문에 실제 존재해야 하며 형식·길이·식별정보를 검사한다. 스키마 준수는 의미 정확도가 아니다.
- **현재 기술:** Structured Outputs 직접 분류다. pgvector나 벡터 검색은 구현·사용하지 않는다. 실제 상황 요약은 아직 빈 상태다.
- **정확도:** 같은 표본에서 키워드·LLM을 사람이 확정한 정답과 대조해야 한다. 모델 간 일치율을 정확도로 부르지 않는다. 검수 예시로 지침을 개선한다면 개발용과 최종 평가 표본을 분리한다.
- **승인한 보완 설계:** 유사 과거 사례는 원래 제출 기획에 포함됐지만 현재 미구현이다. RAG는 유사 과거 신고·수리 자료의 근거 검색 보조다. 다른 신고 사실을 현재 신고의 자동 라벨에 섞지 않는다. 임베딩→pgvector 기준일·권한 필터 검색→출처 연결 요약→담당자 대조를 계획한다. 실제 API·DB 추가 구현은 승인 범위에 포함하지 않는다.
- **검색 검증 계획:** 사람이 표시한 관련 자료 대비 Recall@k, 기준일·권한 누출, 인용의 원문·의미 정확성, 검토 시간을 측정한다. 현재 실측값은 없다.
- **비용:** 반환 사용량의 실행별 추정치를 전체 비용·처리량으로 외삽하지 않는다. 고정 50건 이후 전체 7,502건과 데모 요약 호출은 사용자가 승인했고 결과를 기다린다.

## 제출 전

현재 원문·집계·모델 시험 상태와 최종 배포 버전이 같은지 확인한다. 예선 4분, 결선 8분을 직접 재고 동일 버전의 장애 대비 녹화를 준비한다. 보고서·노트·근거표·QA는 함께 갱신한다.

## 제출 기획과 실제 구현의 차이

부록 6의 대조표를 연다. 요청서는 원래 기획의 담당자 결정을 구체화했다. 별도 부품 추출과 유사 사례 검색은 미구현이다. 신고를 묶는 방식은 고정 증상 코드이며 자유 군집화나 벡터 검색이 아니다. 키워드는 LLM 연결 전 임시 기준선이고, LLM을 대체하기로 한 판단이 아니다. 왜 이 순서인지와 다음 검증은 ADR-017에 기록했다.

## 결선에서만 덧붙이는 후속 조사 설명 · 10초

“요청서 다음에는 조사 질문을 세우고 정비 기록과 검사로 확인해야 합니다. 이 흐름은 후속 설계이며, 지금 원인을 추정하거나 확인한 기능은 아닙니다.”

결선 10장 100초 중 마지막 10초에 위 문장을 넣고 총 480초를 유지한다. 예선 본문에는 넣지 않는다. 질문이 나오면 공통 부록 7을 연다. 원문에 있는 관찰 내용, 조사 가설, 필요한 자료, 확인 결과를 별도로 저장하는 설계다. 정비 진단·고장 코드·부품 검사·작업/생산 이력은 자료 요구사항이며 아직 연결한 자료가 아니다. 실제 현대·기아 사례의 원인을 알아낸 듯한 예시는 넣지 않는다. 근거 부족이면 가설을 보류하고 다른 가능한 설명을 남긴다. ADR-019/S17을 근거로 하며 효과 수치는 없다.
