# ADR-009: 데모 목표 = 조사 준비 끝내기, 주인공 = 조사 요청서

> **2026-10-09 현재 적용:** 조사 요청서 저장 흐름은 공개 배포 완료다. 요약은 [ADR-024](ADR-024-source-summary-selection.md)의 기존 AI 요약 인용, 선행 기간은 [ADR-025](ADR-025-designated-pe-comparison-context.md)의 지정 PE 대비다. 저장일은 실제 저장 시각이며 과거 확인 가능일과 구분한다. 아래는 최초 설계 기록이다.

- 상태: 채택
- 날짜: 2026-10-08 (사전 작업, 시안 검토 후)

## 배경
시간 재생과 "NHTSA보다 209일 먼저"를 보여주는 시안은 분석 결과로는 흥미롭지만, 심사위원 입장에서 "그래서 이 제품으로 무엇을 하죠?"가 남았다. 경보를 보여주는 데서 끝나면 사용자가 일을 끝내는 장면이 없다.

## 결정
- 데모의 목표를 **경보 보여주기 → 조사 준비 끝내기**로 바꾼다. 한 가지 업무를 끝까지 보여준다: 담당자가 반복되는 화재 신고를 발견하고(신고 원문 → 신호), 원문을 검토하고(AI 집계 클릭 → 원문 → 인용/제외), 근거가 연결된 조사 요청서를 만들어 확정·저장한다(.md 다운로드 + 결정 기록).
- 주인공은 **조사 요청서**, 대시보드는 그것을 만드는 작업 공간이다.
- 요청서에는 실제 데이터로 채울 수 있는 것만 넣는다: 대상·기준일, 증가와 경보 근거, 반복 발생 상황, 인용 신고 번호, 아직 확인되지 않은 사항, 내부 AS·생산 이력 확인 항목, 담당자 판단과 다음 조치. LLM 문장은 상황 요약 한 칸이고, 그 인용 번호는 근거 목록 안에 있어야 한다(테스트).
- 209일은 요청서의 날짜로 보여준다: "이 요청서 작성 가능일 2018.09.01 / NHTSA 조사 개시 2019.03.29". 결과물과 검증을 한 장면으로 묶는다.
- 데모 고정 사례: HYUNDAI SONATA · 화재·과열 · 2018년 8월 접수분.
- 원문 링크: NHTSA에서 신고 한 건마다 열리는 공개 페이지는 확인하지 못했으므로, ODI 번호와 앱 안 원문으로 연결한다. 외부 링크는 당일 확인된 경우에만.
- 범위 고정: 이 흐름 하나가 배포까지 끝나기 전에는 전망 띠, 시간 재생 애니메이션, KPI, 사례 재생 화면, 최신 데이터 모드에 손대지 않는다(P2).

## 결과와 트레이드오프
- 시연에 시작(신고 더미)과 끝(저장된 요청서)이 생긴다. 원인 분석을 끝냈다고 주장할 필요가 없다.
- 담당자가 AI 라벨을 [제외]하는 장면(예: 후미등 소켓이 녹는 신고가 화재·과열로 묶임)이 "사람이 판단한다"를 보여준다.
- 관제 화면 요소(KPI, 전망 띠)는 줄어든다. 탐지 검증 결과는 요청서 저장 직후 카드와 검증 패널로만 보여준다.
