# ADR-017: 제출 기획과 실제 구현의 차이를 기록한다

- 상태: 채택 (사용자의 기록 요청; 미구현 기능의 완료 승인이 아님)
- 기록일: 2026-10-09
- 관련: ADR-004, ADR-009, ADR-011, ADR-013, ADR-016

## 사용자가 공유한 제출 기획

아래는 사용자가 2026-10-09 대화에서 공유한 서류 기획안이다. 이 기록일을 기획안 작성일이나 제출일로 해석하지 않는다.

> 신고 원문 → LLM 라벨 추출 → 시계열 집계 → 통계적 변화 탐지 → 근거 브리프 | 과거 시점으로 되감는 백테스트로 검증
>
> ① 신호 추출 LLM이 신고 원문에서 증상·부품·위험 요소(화재/충돌/부상)를 뽑아내고, 같은 의미의 신고를 하나로 묶음
>
> ② 변화 탐지 묶인 신고의 추이를 통계로 감시해 평소보다 유의하게 늘어난 것만 경보 (경보 여부는 LLM이 아닌 통계가 결정)
>
> ③ 신호 브리프 경보마다 근거 신고 원문·추세·유사 과거 사례를 제시 → 담당자가 조사 착수/보류/기각을 결정
>
> ④ Time-Travel Backtest 과거 시점으로 되감아 그때까지의 데이터만으로 탐지하고, 실제 NHTSA 조사 개시보다 얼마나 먼저 신호를 봤는지 측정

## 대조 결과

| 제출 기획 | 현재 구현과 검증 상태 | 차이의 성격 |
|---|---|---|
| 원문에서 증상·위험 요소 추출 | 정제 원문을 직접 LLM에 입력하고 16개 범주의 대표·보조 증상, 위험 상황, 심각도, 근거 인용, 한국어 요약을 받는다. 스키마·원문 인용·식별정보 검사는 구현했다. 전체 분류와 사람 정답 검증은 미완료다. | 접근 유지, 구현·품질 검증 진행 중 |
| 부품 추출 | 일부 분류명이 부품/계통을 나타내지만 별도의 부품명·부품 식별자 추출 필드는 없다. | 명시적인 미구현 범위 |
| 같은 의미의 신고를 묶음 | 동일한 분류 코드로 묶어 차종×증상×접수월의 고유 신고를 센다. 자유로운 의미 군집화나 벡터 검색으로 묶는 방식은 아니다. | 구현 방법을 고정 분류표로 구체화 |
| 통계가 변화 탐지·경보 결정 | 이전 12개월 평균을 이용한 포아송 상측확률과 최소 건수 규칙. 공개 제품·38사례 평가에는 현재 키워드 기준선을 사용한다. | 역할 분리는 유지, AI 연결 전 임시 기준선 상태 |
| 근거 원문·추세·브리프 | 실제 원문 인용·제외와 기준일까지의 추이를 제공한다. LLM 상황 요약의 생성·인용 검사·캐시와 export 연결을 오프라인 구현·검증했고 독립 검수 중이다. 실제 생성·품질은 미검증이며 공개 화면에는 미생성으로 표시한다. | 일부 완료, AI 브리프는 실사용 검증 전 |
| 유사 과거 사례 제시 | 현재 경보에 미리 연결한 조사 사례의 사후 결과는 보여주지만, 유사 사례를 검색해 브리프에 제시하는 기능은 없다. pgvector·RAG도 미사용이다. | 원래 기획에 포함된 미구현 기능; 새로운 약속으로 바꾸어 설명하지 않음 |
| 담당자 착수·보류·기각 | 근거 검토 후 판단·다음 조치를 조사 요청서로 확정하고 Markdown과 판단 이력을 저장한다. | 사용자 업무의 끝을 명확히 하는 구체화 |
| 과거 시점 백테스트·선행일수 | 접수일 기준으로 38개 사례의 기준일까지 신고를 잘라 완료월 경보를 재계산한다. 공식 조사 개시일과 확인 가능일의 차이를 측정한다. | 접근 유지; 당시 공개 파일의 수정 이력까지 복원하지 못하는 한계를 명시 |

## 왜 이 순서로 구현했는가

**조사 요청서까지 연결한 이유.** 사전 ADR-009(2026-10-08)은 경보와 선행일수만으로는 담당자가 어떤 일을 끝내는지 불명확하다고 기록했다. 요청서는 원래 기획의 담당자 판단을 원문 근거·미확인 사항·다음 조치와 함께 보존한다. 사용자는 당일 이 핵심 흐름 유지와 보완을 승인했다. 따라서 이것은 탐지 목적을 바꾸는 전환보다 업무 결과물을 구체화한 결정이다. 실제 업무 시간 단축이나 구매 의사가 입증된 것은 아니다.

**키워드 기준선을 먼저 배포한 이유.** 사용자는 비용 확인을 위해 LLM 50건 시험까지만 승인했다. 처음에는 크레딧 부족, 이후 요청 제한이 실제로 발생했다. 이 기간에도 집계·통계·원문 연결·저장 흐름을 검수할 수 있도록 명세에 있던 키워드 기준선을 사용했다. 키워드가 LLM보다 낫다는 결론을 내린 적은 없으며, 기준선 배포를 제출 기획의 AI 기능 완료로 제시하지 않는다.

**분류 표와 검사를 먼저 고정한 이유.** 집계하려면 같은 의미의 분류가 월마다 일관되어야 한다. 고정 코드와 원문 인용은 분류 결과를 비교·추적할 수 있게 한다. 다만 형식과 인용의 유효성만으로 의미상 정확성이 증명되지는 않는다. 실제 사람 정답과의 비교가 완료 조건이다.

**유사 사례 검색을 다음 구현으로 둔 이유.** 이 기능은 원래 기획에 있었다. 초기 구현에서 빠졌다는 사실을 인정하고 ADR-016에 보완 설계를 남긴다. 다른 사건의 사실이 현재 신고의 라벨에 섞이거나 기준일 이후 조사 결과가 검색되는 것을 막아야 한다. 먼저 직접 분류의 정확도를 측정하고, 검색은 담당자의 근거 검토에 보태는 순서를 사용자가 선택했다. pgvector는 그 검색을 구현할 후보이며 기획의 목표 자체는 특정 벡터 DB 사용이 아니다.

## 적합성에 대한 판단과 남은 조건

- 총괄 판단: 조사 요청서로 업무를 끝내고 근거를 추적하는 방식은 제출 기획의 담당자 결정과 도입 가치 설명에 적합하다. 이는 설계 판단이며 현업 효과 실측이 아니다.
- 원래 기획의 LLM 분류·유사 사례·근거 브리프를 빼는 편이 더 낫다고 결론 내리지 않는다. 현재 미구현 범위와 보류 사유를 함께 공개한다.
- 직접 LLM 분류의 동일 표본 비교와 사람 정답 검수를 우선한다. 오류 유형·비용·시간을 확인한 뒤 전체 실행을 결정한다.
- 별도 부품 추출을 추가한다면 원문에 명시된 부품만 추출하고, 증상 코드·문장 인용과 구분된 계약 및 정답 평가가 필요하다. 현재 미구현이다.
- 검색 구현 전 관련 문서 정답, 접수일·자료 이용 가능일·권한 필터, 인용 의미 정확성과 검토 시간 측정 계획을 갖춘다. ADR-016의 검색 평가 지표는 아직 미측정이다.
- 발표에서는 `제출 기획 → 현재 완료 → 미완료 → 보완 이유 → 다음 검증`을 한 표로 보여준다. 기획 문서의 과거 내용을 수정해 차이를 지우지 않는다.

## 후속 변경: 대표 신고의 기존 AI 요약 인용 (2026-10-09)

위 대조표와 구현 순서 설명은 최초 기록 당시의 상태를 보존한다. 이후 상황 요약은 [ADR-023](ADR-023-structured-brief-citations.md)의 문장별 자유 서술을 거쳐 [ADR-024](ADR-024-source-summary-selection.md)의 대표 신고 선택·기존 요약 인용으로 바뀌었다. 인용 형식 검사를 통과한 종합 문장에서도 제공된 요약과 인용의 의미 대응이 어긋난 사례를 총괄이 확인했고, 사용자가 “신고별 AI 요약을 그대로 인용하고 번호 연결”을 선택했다.

현재 모델은 제공된 최대 10개 근거에서 대표 번호 1~3개만 선택한다. 프로그램이 실제 경보 통계문과 각 신고의 기존 `summary_ko`를 `(#번호) 기존 요약`의 독립 줄로 연결하며 새 상황이나 복합 주장을 만들지 않는다. 표시명은 “대표 신고 요약 (AI 요약 인용·담당자 검토)”다. 기존 AI 요약 자체의 원문 의미 정확성과 신고 분류 정확도를 입증한 변경은 아니며, 선택된 신고가 전체 신고의 동일 상황·빈도·공통 원인을 뜻하지 않는다.

사람 정답 검수는 자료를 준비한 뒤 사용자의 도메인 지식·시간 제약으로 당일 완료하지 않기로 했다([ADR-020](ADR-020-independent-blind-human-review.md), S23). 분류 정확도는 미측정이고 전문가의 독립 검수는 후속 미완료 과제다. 기존 기획과 준비 이력을 지우거나 AI가 만든 정답으로 대체하지 않는다.
