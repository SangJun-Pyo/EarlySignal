# ADR-019: 조사 가설과 확인 절차는 후속 설계로 구분한다

- 상태: 채택 (설계·발표만, 기능 구현은 이번 범위에서 제외)
- 날짜: 2026-10-09
- 관련: ADR-004, ADR-009, ADR-016, ADR-017

## 배경

사용자는 실제로 고객 신고가 들어오면 먼저 조사할 대상을 찾고, 가능한 원인도 어느 정도 좁힐 수 있는지 물었다. 이어 **현재 제품 완성 우선, 가설·확인 절차는 설계와 발표에 추가**를 선택했다.

현재 제품은 과거 NHTSA 소비자 신고를 접수월별로 집계한 정적 데모다. 새 고객 요청의 실시간 수집이나 정비·생산 기록 연결은 구현하지 않았다. 선행일수는 공식 조사 개시일과의 차이이며 사고 발생 전 예측 성능을 뜻하지 않는다.

## 결정

1. 이번 제품은 신고 근거를 검토하고 조사 요청서를 저장하는 흐름을 완성한다. LLM 분류는 원문에 나타난 증상과 상황을 측정하며, 원문 밖 원인을 만들어 넣지 않는다.
2. 후속 업무는 `신고 원문에 명시된 내용 → 조사할 가설 → 가설을 지지·반박할 추가 자료 → 담당자의 확인 결과`로 설계한다. 각 단계의 상태와 출처를 따로 보존한다. 아직 수행하지 않은 조사를 완료처럼 표현하지 않는다.
3. 가설을 제시하려면 근거 신고 ID, 원문에 명시된 내용과 추론의 구분, 다른 가능한 설명, 필요한 확인 자료를 함께 보여준다. 근거가 부족하면 가설을 제시하지 않는 결과도 허용한다. 확률 수치는 보정·검증 전에는 붙이지 않는다.
4. 필요한 자료는 해당 가설에 따라 정비 진단·고장 코드, 실제 부품 검사, 작업 기록, 부품 공급·생산 이력, 운행 조건 등이 될 수 있다. 이는 도입 설계의 자료 요구사항이며 현재 확보한 자료 목록이 아니다. 접근 권한과 자료 이용 가능 시점을 확인해야 한다.
5. 유사 신고·과거 사례 검색은 ADR-016의 보완 경로다. 표현이 비슷하다는 이유로 같은 원인을 부여하지 않으며, 과거 조사 결론을 현재 경보의 탐지 입력에 넣지 않는다.
6. 발표에서는 위 흐름을 **후속 설계 / 미구현**으로 표시한다. 현재 출력 검사 통과율, 사람 정답 기반 분류 정확도, 통계 백테스트, 원인에 관한 후속 확인을 별개로 설명한다.

## 왜 이 범위인가

신고에는 운전자가 관찰한 소리·연기·동력 상실 등 증상이 담길 수 있지만 내부 부품의 검사 결과나 작업 이력이 없는 경우가 많다. 같은 증상에 다른 설명이 가능하고, 신고자가 추정한 원인도 독립 확인이 필요하다. 따라서 지금의 데이터로 확정할 수 없는 내용을 출력하기보다 조사할 질문과 확인 자료를 정리하는 방식이 제품 목적에 맞는다고 판단했다. 이는 설계 판단이며 현업 효과를 실측한 결론은 아니다.

## 다음 검증

- 현업 담당자가 실제 조사 업무에서 이 단계와 자료를 사용하는지 확인한다.
- 가설의 근거 연결, 반례·대안 누락, 근거 부족 시 보류, 기준일·권한 위반을 평가한다.
- 이후 독립적으로 확인된 정비·검사 결과와 비교할 때 평가 표본과 판정 지침을 먼저 정한다.
- 요청서 준비 시간과 추가 자료 요청의 유용성을 측정한다. 현재 효과 수치는 미측정이다.

## 결과와 절충

현재 제품의 완료를 늦추지 않고 실무 도입 후 필요한 다음 단계를 설명할 수 있다. 대신 고객 신고만으로 원인을 알아낸다는 주장은 하지 않으며, 실제 데이터 연결·가설 생성·검증 기능은 별도 개발과 평가가 필요하다.
