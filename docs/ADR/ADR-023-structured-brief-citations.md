# ADR-023: 상황 요약은 문장별 서술과 제공된 근거 번호로 생성한다

- 상태: ADR-024로 대체됨 (문장별 자유 서술 설계와 검증 이력은 보존)
- 날짜: 2026-10-09
- 관련: 이슈 #12, ADR-015, SPEC Step 10, S27

## 관측한 문제
실제 동일 18개 경보의 54응답이 모두 거부됐다. 실패 분류는 uncited_narrative 37회, outside_evidence_citation 14회, unsupported_narrative_number 2회, unsupported_conclusion 1회다. 반환 사용량 비용은 $0.0211592였다. 추가 진단 1응답($0.0004)은 첫 문장에 인용이 없고 둘째 문장에 제공된 번호가 있었으며 실패했다. 원문과 실패 응답은 저장하지 않았다. 모든 실패가 같은 원인이라고 단정하지 않는다.

사전 프롬프트의 '2~3문장/둘째 문장 인용'과 런타임의 '1~3문장/각 문장 인용'이 함께 전달된다. 이는 문장마다 근거가 있어야 하는 실제 검증 규칙과 충돌한다.

## 결정
- §2의 프롬프트를 현재 구현에 맞는 하나의 규칙으로 정리한다. §1의 신고 라벨링 프롬프트와 라벨 정책은 변경하지 않는다.
- 내부 API 응답은 `sentences` 배열(1~3개)이며 각 항목은 `text`와 `citation_ids`다. `text`는 제공된 요약·플래그에 있는 상황만 서술하는 한 문장이고 숫자·수량·인용 표식을 쓰지 않는다. `citation_ids`는 비어 있지 않으며 해당 호출에 제공된 최대 10개 신고 번호의 enum으로 제한한다.
- 코드는 각 항목이 실제로 한 문장인지 확인한 뒤 `(#번호)`를 붙인다. 복수 문장을 한 항목에 넣어 인용 없는 앞 문장을 자동 보정하지 않는다. 고정 통계문과 합친 결과에 기존 같은 칸·접수월·미래 정보·수량·개인정보·단정 검증을 그대로 적용한다.
- 공개 계약은 기존 문자열 `briefs` 그대로다. 내부 응답 스키마와 프롬프트 해시가 달라져 이전 캐시는 재사용하지 않는다. 사용량·실패 기록과 최초 생성+최대 2회 재생성 제한을 유지한다.
- 오프라인 합성 회귀 테스트 후 독립 검수를 거쳐 통합한다. 실제 호출은 총괄이 같은 18개 경보 중 첫 1개를 확인한 뒤 나머지를 실행한다. 이 구현 세션은 API를 호출하지 않는다.

## 한계
번호와 문장 인용의 연결은 검사할 수 있지만 서술의 의미가 실제 신고에 맞는지는 별도 원문 검토가 필요하다. 이번 사용자는 도메인 지식·시간의 제약으로 사람 정답 검수를 취소했으며 분류 정확도는 미측정이다. 상황 요약 인용 검사 통과율과 신고 분류 정확도를 혼동하지 않는다.
