# ADR-024: 대표 신고의 기존 AI 요약을 그대로 인용한다

- 상태: 채택
- 날짜: 2026-10-09
- 관련: 이슈 #12, ADR-015, ADR-023, SPEC Step 10, S28

## 관측한 문제와 사용자 선택
ADR-023의 문장별 구조화 형식은 첫 실제 1응답에서 인용 형식 검사를 통과했다(반환 사용량 $0.0004956). 그러나 총괄이 제공된 한국어 요약과 대조하자, 엔진 위치·연기·화재를 함께 주장한 문장에 연결된 신고 중 일부는 차량 화재만, 일부는 연기만 언급했다. 문장의 모든 주장에 각 인용이 대응하지 않았다. 이 결과는 공개하지 않았고 나머지 18개 경보 확대도 중단했다. 이는 원문 전체나 신고 분류 정답 정확도를 검수한 결과가 아니다.

총괄은 자유 종합과 신고별 기존 AI 요약 인용을 선택지로 제시했다. 답변 전에는 기존 허용 범위에서 보수적인 검토본 기본안으로 후자를 준비한다고 알렸고, 이후 사용자가 '신고별 AI 요약을 그대로 인용하고 번호 연결 (추천)'을 명시적으로 선택했다.

## 결정
- 모델은 호출에 제공된 최대 10개 근거의 번호 enum에서 `selected_ids` 1~3개만 선택한다. 새 문장이나 복합 상황을 쓰지 않는다. 중복·범위 밖 번호는 거부한다.
- 프로그램은 선택된 각 신고의 `summary_ko`를 한 줄씩 `(#ODINO) {기존 요약}`으로 연결한다. 원문의 요약 문자열에 새 단어를 붙이거나 문장·숫자·마침표를 고치지 않는다. 첫 통계 문장은 기존 실제 경보 값으로 작성한다.
- 기존 같은 칸·접수월·미래 정보·수량·개인정보·단정 검증을 유지한다. 기존 요약이 복수 문장·인용 표식·줄바꿈·외곽 공백을 포함하여 그대로 인용할 수 없거나 기존 검증에서 거부되면 그 생성은 실패한다. 실패를 통과시키려 문자나 검사를 바꾸지 않으며 최초 선택 뒤 재선택은 최대 2회다. 통과한 결과만 공개한다.
- 표시명은 대표 신고의 기존 AI 요약 인용임을 분명히 한다. UI 변경은 별도 S29에서 수행한다. 공개 `briefs` 문자열 계약은 그대로다.
- 캐시는 모드·프롬프트·스키마·기존 입력 해시로 연결해 이전 자유 서술 캐시를 재사용하지 않는다. 성공 기록에 `selected_ids`를 보존하고, 읽을 때 선택 ID와 현재 요약으로 다시 구성한 문자열과 정확히 일치해야 공개한다.
- §1 신고 라벨링 프롬프트와 분류 캐시는 변경하지 않는다. 구현은 오프라인으로 검사하며 실제 호출은 총괄이 통합·독립 검수 후 승인된 동일 경보 범위에서 수행한다.

## 한계
이 방식은 새 상황을 합성하면서 생기는 과장을 줄인다. 이미 작성된 신고별 AI 요약 자체가 원문을 과장하거나 왜곡했는지는 자동으로 확인하지 못한다. 원문 의미 대조와 사람 정답 검수는 여전히 별도 업무이며 분류 정확도는 미측정이다. 선택된 최대 3개 신고는 대표 인용이며 전체 신고의 동일 상황·빈도·공통 원인을 뜻하지 않는다.
