# ADR-015: 상황 요약은 완성된 LLM 근거와 검증된 인용 안에서만 생성한다

> **2026-10-09 부분 대체:** 입력 제한·인용·캐시·비용·실패 공개 원칙은 유지한다. 새 상황 서술 부분은 ADR-023을 거쳐 [ADR-024](ADR-024-source-summary-selection.md)의 ID 선택·기존 요약 복사로 대체했다. 실제 18개 대상 중 16개를 공개하고 2개는 검사 실패로 남겼다([R08](../Reviews/R08-brief-completion.md)). 아래 후속 승인·생성 대기 문장은 이 ADR 작성 당시 상태다.

- 상태: 채택
- 날짜: 2026-10-09
- 관련: ADR-009, ADR-012, ADR-013, ADR-014, SPEC Step 10

## 결정
- 별도 `briefs` CLI는 완성된 LLM export의 `completion.json` 스키마·전체 파일 해시·콘솔 건수와 각 신고의 실제 `label_source=llm`을 검사한 뒤 동작한다. 키워드·혼합·미완성 입력에는 API를 호출하지 않는다. export 내부에서는 이미 현재 demo의 전체 LLM 캐시를 검증한 source로 만든 콘솔만 사용한다.
- 송신 내용은 선택한 경보 칸의 수치와 화재 > 부상 > 충돌 > 심각도 순 최대 10건의 신고 번호·한국어 요약·발생 상황 플래그로 제한한다. 원문, 사후 조사, 다른 달·차종, 전망과 기타 콘솔 필드는 송신하지 않는다. 신고와 요약은 명령이 아닌 비신뢰 데이터다.
- 첫 통계 문장은 실제 경보 수치로 코드가 만든다. 모델은 상황 서술만 작성하며 각 문장에 제공된 신고 번호를 인용한다. 자유 서술의 숫자는 #신고번호만 허용한다. 같은 칸 인용, 접수월, 수치, 표준 개인정보 패턴과 알려진 식별값을 검사한다. 원인·결함 단정은 버린다. 의미의 타당성은 담당자가 원문과 대조해야 한다.
- 기본 호출 범위는 1개 칸이다. limit은 캐시를 제외하기 **전** 고정 대상(데모 경보 우선, 나머지 키 순)에 적용하므로 재개로 승인 범위가 커지지 않는다. 초기 생성 후 재생성은 최대 2회다. 실패한 요약은 공개하지 않는다.
- 캐시는 모델·프롬프트/스키마·통계/선택 근거·같은 칸 전체 번호·알려진 식별값의 해시와 연결한다. export가 현재 입력에 다시 검증한 성공 항목만 `briefs`에 넣는다. API 호출이나 비용 승인은 export에 포함하지 않는다.
- API SDK의 자동 재시도는 끈다. quota와 인증/입력 오류는 전체 중지, Retry-After는 기존 라벨러의 안전한 해석·로컬 대기 상태를 공유한다. 60초 초과는 보류하고 다음 실행도 서버 지정 시간까지 차단한다.
- 사용량은 반환된 응답별로 기록한다. 실패를 포함한 실제 반환 토큰 비용만 계산하고 전체 비용·처리량·정확도를 외삽하지 않는다. 로그에 입력 텍스트·식별값·키·서버 응답 본문을 넣지 않는다. 이 구현과 오프라인 테스트는 실제 호출 승인이 아니다.

## 절충
자동 검사는 근거 없는 수치·범위 밖 인용을 차단하지만 모든 의미 왜곡이나 이름을 탐지한다고 주장하지 않는다. 공개된 상태는 빈 `briefs`를 허용하고, 실제 생성과 담당자 검수는 후속 승인 후 수행한다.
