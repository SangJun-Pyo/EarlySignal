# ADR-020: 독립 사람 검수 표본은 예측을 가리고 정답을 보존한다

- 상태: 채택 (SPEC Step 7 사람 검수 30건 준비, API 호출 승인 아님)
- 날짜: 2026-10-09
- 관련: ADR-012·013·016·018, SPEC Step 7

## 결정
1. 기존 seed42 첫 50건은 인용 정책 개선에 사용한 개발 시험이다. 그 표본의 출력 검사 통과와 사람 확인은 운영·오류 진단이며 최종 분류 정확도로 보고하지 않는다. 추가로 확인한 #11222309도 이 50건 안에 있다.
2. 독립 표본은 현재 demo의 고유 신고에서 그 50건을 제외하고 별도 고정 seed `human-review-v1`의 SHA256 순서로 30건을 미리 선택한다. 성공 응답·모델 예측·두 방법의 불일치를 보고 표본을 고르지 않는다. 신고 번호, 입력 해시, 표집 규칙과 모집단 ID 지문을 비공개 대응표·manifest에 잠근다.
3. 모델·분류 프롬프트/스키마 해시·인용 정책과 해당 정책 구현 해시·검수 기준을 잠근다. 기준이나 입력이 바뀌면 기존 파일을 덮어쓰지 않고 오류로 중지한다. 표본을 본 뒤 모델을 고치면 그 표본도 개발 자료가 되며 새 평가 표본이 필요하다.
4. 사람에게 제공하는 CSV는 익명 검수 번호, 실제 모델 송신과 동일한 정제 원문(공백 정리·알려진 식별값 가림·최대 1,500자), 빈 정답·상태·근거·메모 칸만 담는다. 모델/키워드 예측, AI 요약·선택 인용, ODI 번호와 차종 메타데이터는 보이지 않는다. 원문 자체의 차종 표기는 임의로 삭제하지 않는다. CSV와 ODI 대응표는 서로 다른 비공개 파일이고 권한은 0600, 디렉터리는 0700이다.
5. 검수자는 고정된 16개 범주의 주 라벨을 원문으로 먼저 판단하고 불명확함·판정 불가를 기록한다. 정답을 먼저 잠근 뒤 예측과 대조한다. 애매한 문서는 가능하면 두 번째 사람도 예측을 보지 않고 검토한다. 한 사람만 검수했으면 그 사실을 표시한다. 사람 정답이 없으면 정확도는 미측정이다.
6. 준비를 다시 실행해도 기존 정답·메모를 그대로 보존하고 원문·대응표·잠금값만 검사한다. 기존 파일이 손상되거나 표본/원문이 바뀌면 중지한다. 개발용 `sample60_compare.csv`는 기존 개발 50건을 포함한다는 메모를 별도로 쓰고, 이미 있는 파일은 다시 덮어쓰지 않는다. 실제 사람 정답은 독립 비공개 파일에서만 관리한다.
7. 이 30건으로 보고할 것은 고정 표본의 방법별 정답 일치 건수/분모, 판정 불가와 출력 실패, 오류 유형이다. 16개 범주의 안정적 성능, 전체 7,502건·다른 시장의 정확도, LLM 우월성, 경보·사고·원인 성능을 보증하지 않는다. 범주 정의의 애매함과 작은 표본의 한계를 남긴다.

## 절충
비공개 원문도 소비자 진술이며 사실을 독립 확인한 자료는 아니다. 정제와 인용 일치 검사는 완전한 익명화·의미 정확성 보증이 아니다. 준비 경로는 API를 호출하거나 키·`.env`를 읽지 않으며 결과와 검수는 후속 사람이 수행한다.

## 변경 이력
- 2026-10-09, 사용자 결정 / S23 / 이슈 #7: 독립 30건 자료를 전달하고 사용자가 검수를 시도했으나, 도메인 지식과 공모전 시간 제약 때문에 당일 검수를 완료하지 않기로 했다. 정답은 작성되지 않았고 평가 실행·정확도 산출은 중단한다. 자료 준비를 검수 완료로 표시하지 않으며 AI가 대신 만든 정답으로 대체하지 않는다. 출력 형식·인용 일치 검사, 키워드와 LLM의 일치율, 과거 시점 백테스트는 각각의 검증 범위로만 보고한다. 전문가의 독립 검수는 후속 과제로 남긴다.
- 2026-10-09, 이슈 #3 / S22: 손상 파일 중지 조건을 CSV의 각 행에 적용한다. 행의 키 집합은 명시된 열과 같고 모든 셀은 문자열이어야 한다. `DictReader`가 누락 셀에 채우는 `None`과 추가 셀의 `None` 키·목록 값을 거부하며 정상적인 빈 문자열은 허용한다. 거부 시 기존 파일을 변경하지 않는다. 표집·라벨·인용 정책은 바꾸지 않으므로 manifest 재생성은 필요 없다.
